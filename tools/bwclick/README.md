# bwclick

Sends a real pointer click through `zwlr_virtual_pointer_v1`.

Hyprland has no click dispatcher and this machine has no `uinput` module, so
there was no way to check whether a widget's `onclick` actually fires - which
is how a broken click path survived several rounds of "fixed". Hyprland does
advertise the wlroots virtual-pointer protocol, and this is a ~60 line client
for it.

    tools/bwclick/bwclick X Y [SCREEN_W SCREEN_H]

Rebuild with:

    cd tools/bwclick && gcc -O2 -o bwclick main.c vp.c $(pkg-config --cflags --libs wayland-client)

`vp.c` / `vp.h` are generated by `wayland-scanner` from
`wlr-virtual-pointer-unstable-v1.xml`; they are committed so the tool builds
without hunting for the protocol file.

## What it is for

Finding the coordinates of a control and clicking it, so a claim like "the
calendar opens a day now" is a thing you watched happen rather than a thing
you reasoned about:

    hyprctl layers | grep -A1 eww_calendar    # x y w h of the panel
    tools/bwclick/bwclick 1692 281            # click inside it
    eww get cal_view                          # did it change?
