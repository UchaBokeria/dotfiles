## CS001 — This is a workflow library as well as a visual desktop

The copied Superpowers family controls a complete development lifecycle: skill discovery, brainstorming, spec writing, task planning, isolated worktrees, implementation, code review, remediation loops, verification and branch integration. It includes harness mappings for Codex, Gemini, Pi, Hermes and Antigravity. These files are copied operating procedures, not direct quotations of the owner's preferences and not instructions invoked during this audit. The current audit follows the user's read-only scope.

The library is opinionated about repeated failure modes: preserve progress across compaction, hand tasks and reviews over as files, keep workers from spawning redundant reviewers, capture the full per-task git range, verify evidence before claiming completion, and prefer narrowly scoped fixes. This complements the repository's terminal-first engineering environment. It does not itself prove the owner wants every approval or ceremony imposed by every copied file.

## CS003 — Delegation has a cost-control and recovery architecture

SDD uses a fresh isolated worker for each substantial task, one task reviewer returning both spec and quality verdicts, scoped re-review after fixes, and a broad final review. Rounds1–3 resume the implementer;4–5 replace it with a stronger model; the controller adjudicates residuals at the five-round cap and exports every ruling before deleting scratch records. Final review gets one fix wave and one re-review. Minor/out-of-scope observations are ledgered for final triage rather than silently dropped or endlessly widening the current loop. Reviewers do not rerun already-evidenced suites absent a named doubt. These constraints reduce duplicate work but are process intentions, not measured results from this audit.

Its key and screen content travel over HTTP/WS if a non-loopback interface is selected; the token is an access gate, not encryption. ## CS007 — Two helper contracts do not fully match their descriptions

helper.js:163 exports `brainstorm.choice(value, metadata)` emitting a `value` field. server.cjs:513 appends to the events file only when `event.choice` is truthy. Therefore the explicit programmatic choice API is logged to stdout but, without metadata adding choice, is absent from the events file that the agent is told to read. DOM clicks use `choice` and follow the intended path. This is a source-derived gap, not a reproduced live defect.

The reconnect queue is unbounded while disconnected (helper.js:125). Its exponential reconnect delay is capped30s; after15s disconnected it displays a paused overlay and reloads through keyed bootstrap on recovery. Frame options/cards are clickable divs with no built-in keyboard role or key handler, despite the separate frontend guide requiring visible focus and accessible interaction; individual generated content could add that behavior, but the common helper does not.

stop-server.sh:113 deletes an ephemeral session based on the lexical `/tmp/*` prefix after authenticating the target process; it does not canonicalize/validate the session directory against a created-session pattern. It should be understood as an operator-input helper, not a general safe deletion API. `find-polluter.sh` also describes itself as bisection but sequentially runs npm tests, ignores test failures, and shell-splits file names; a preexisting polluted path causes every test to be skipped and ultimately prints a clean conclusion. None of these helpers was run.
