## 4. Subscribe dead-writer accumulation (`daemon.py:84,106-116,526-536,675-678`)

- Prune only on `(ConnectionError, RuntimeError)` from `write/drain` (`daemon.py:113`). Half-closed but backpressured writers raise nothing — they just make `await drain()` (`daemon.py:111`) hang, and since broadcast loops writers sequentially, **one stuck reader stalls every subscriber and every `push_state`** (deltas at `daemon.py:222-225`, approvals at `daemon.py:410`, turns at `daemon.py:284`). No heartbeat, no per-writer timeout, no max-buffer/TTL eviction.
- No unsubscribe op; `subscribed` flag (`daemon.py:526`) never resets; re-`subscribe` on same writer dedups via set but re-sends full state (`daemon.py:534`). Removal only on disconnect (`daemon.py:675-676`) or narrow prune (`daemon.py:115-116`).
- `broadcast` lets any other exception (e.g. `ValueError` from a closing writer) escape mid-loop (`daemon.py:106`): remaining writers unwritten, dead list unprocessed.
- Shutdown path (`daemon.py:1100-1106`) closes writers, but the live-subscriber test never actually subscribes (see §1, `test_shutdown.py:66`), so the fixed bug (subscribe conn blocking `wait_closed`) is guarded by a test that doesn't reproduce it.
