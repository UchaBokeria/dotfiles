## 2. `bin/` launchers — 2 real findings

**F3 (medium). `archpilot-snapshot diff` is blind to new files — the most important change class.** `diff()` (`bin/archpilot-snapshot:114-134`) only walks snapshot→live, reporting `changed`/`deleted`. Live-only files are never listed. Proven empirically: `bin/archpilot-snapshot diff` output omits `src/archpilot/engine/codex.py`, `tests/test_codex.py`, `tests/test_dispatch_strings.py`, `tests/test_ui_theme.py` — i.e. the entire Codex engine is invisible to the "what changed" command. A second loop over live files reporting `added` is the fix.

**F4 (low). `bin/archpilot-ui:7-10` interpolates `$ROOT` into single quotes inside `python3 -c "..."`.** Spaces in path: safe (verified reasoning + quoted `"$@"` on `:12`). But a path containing `'` (apostrophe), backtick, `$`, or `"` breaks the embedded Python or re-triggers shell expansion — silent UI-no-open with the error on stderr. Robust fix: `PYTHONPATH="$ROOT/src" exec /usr/bin/python3 -m ...` instead of string interpolation. Also `readlink -f` (`:6`) is GNU-only (no macOS/BSD) — fine for this Arch-only rice, noting for completeness. `set -euo pipefail` absent: a failed `cd` yields empty `ROOT` → cryptic `/src` import error rather than a clear message.

`restore()` note (informational, design is honest): `shutil.rmtree` then `copytree` per tree (`bin/archpilot-snapshot:88-90`) is non-atomic — a mid-restore failure loses the live tree, recoverable only via the auto-safety snapshot (`:82`). Acceptable given the documented "restart to pick it up" contract; just don't run it with a full disk. Same-second double-`save()` collides on the timestamp stamp (`:41-42`, `mkdir exist_ok=True` + `dirs_exist_ok=True` silently merges) — trivial.
