#!/usr/bin/env bash
# Watchdog for usage-limit stalls in the cloud Claude sessions.
#
# Why this exists: Claude Code 2.1.252 has native quota auto-resume
# (settings.json `autoContinueAtUsageLimit`, default on) — when the 5-hour limit
# stops a session it arms itself and continues when the limit resets. But it
# gives up in four documented cases, and in a detached tmux session on a server
# nobody is there to notice:
#
#   stale             "Usage limit has reset · press enter to continue"
#                     -> waits for a literal Enter keypress. Nothing presses it
#                        here, so the task sits done-but-unresumed forever.
#   cap-exhausted     "Automatic continue stopped after repeated usage-limit
#                      hits" -> disarms; exactly what a long unattended run does.
#   horizon-exceeded  reset is >24 h out (the weekly limit) -> never resumes,
#                        by design.
#   cancelled         typing into the input box silently cancels the armed
#                        continue. Our Telegram poller types into this session,
#                        so an inbound message can kill it. Not detectable from
#                        the pane; see docs/session-autocontinue-plan.md.
#
# This covers the first three. Cron: */2 * * * * — see docs/telegram-widget.md.
#
# Safety rule: only ever act when the pane actually shows one of those states.
# Typing "continue" into a merely-idle session invents work and burns tokens.
