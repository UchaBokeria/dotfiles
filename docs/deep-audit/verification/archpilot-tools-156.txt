262: ### 5.4 eww panels, waybar, rofi, swaync
263: 
264: - **eww** (0.5.0) draws the control centre, network/bluetooth/VPN, audio,
265:   calendar, clocks, notification history and stickers. Its scripts live in
266:   `eww/scripts/` and `scripts/`.
267: - Known eww traps (full list in the cheatsheet):
268:   - `:onclick` goes on the **button**, not a wrapping eventbox.
269:   - A script an eww handler launches must detach itself (the `BW_DETACHED`
270:     re-exec) before it calls `eww update`, or the two deadlock.
271:   - `(input)` cannot work in these panels, so text entry goes through rofi
272:     prompts.
273:   - A `defpoll` cannot read variables.
274:   - `eww reload` keeps serving the last config that parsed. The real symptom of
275:     a broken file is `eww open x` → "No window named…".
276:   - A button's text needs its own `label` selector.
277:   - Icons need `$font_icon` = `"Symbols Nerd Font"`, and only that family
278:     works.
279: - **waybar** has switchable variants: `waybar/variant capsule|pill|dock`.
280:   Workspace pills are custom modules driven by
281:   `scripts/blackwall-bar-workspaces`, because the native module dispatches in
282:   `.conf` syntax, which the Lua config rejects.
283: - **rofi**: all launchers share the generated `rofi/shared/blackwall.rasi`. The
284:   layouts in `rofi/blackwall/` hold geometry only.
285: - **swaync** is the notification daemon, and mako is masked.
286:   `blackwall-notifyd` passively logs every notification to
287:   `~/.local/share/blackwall/notifications.jsonl`. Notification actions are
288:   named `default`. `swaync-client -dn` turns DND **on** and `-df` turns it off,
289:   the reverse of how they read.
290: - **`blackwall-watch`**: background checks (disk, failed units, pacnew, updates
291:   and more), each raising a notification with an action. It never upgrades
292:   anything by itself.

295: 
296: User-facing examples: `setwall`, `blackwall-shot` / `-shots` (capture, OCR,
297: translate, ask ArchPilot), `blackwall-clip`, `blackwall-net`, `blackwall-vpn`,
298: `blackwall-audio`, `blackwall-quiet`, `blackwall-cal`, `blackwall-clean`,
299: `blackwall-snapshot`, `blackwall-undo`, `blackwall-glass`,
300: `blackwall-selftest`. Each is documented in the cheatsheet.

302: Security-sensitive: **`blackwall-setkey`** runs as root to edit VPN

304: `PreUp`, `PostDown` and `pppd-plugin`, because a writable `PostUp` would be a
305: root shell. Keep it that strict.

307: ### 5.6 ArchPilot (`archpilot/`)
308: 
309: **Full handover: `archpilot/handover.md`.** It covers the architecture, the
310: safety gate, every key, config, protocol and CLI command, a plan for adding
311: an opencode engine, and the bugs found during this handover. The summary
312: below is the short version.
313: 
314: - A GTK4 window (`SUPER+~`) plus a daemon (`archpilotd`, a systemd user unit)
315:   that speaks newline-JSON over `$XDG_RUNTIME_DIR/archpilot.sock`.
316: - It has two modes. **ask** is read-only, enforced structurally. **action** can
317:   change the machine, behind a PreToolUse approval gate
318:   (`hooks/pretooluse.py`, which fails closed; see `docs/hook-contract.md`).
319:   Three safety layers apply, in order: a denylist, a reversibility classifier
320:   (`policy.py`), and auto-commit of dotfile changes (`archpilot undo`).
321: - `sudo` goes through a PATH shim and an askpass broker, so the model never
322:   sees the password.
323: - **Engines:** `engine/claude_code.py` drives the `claude` CLI on a Claude
324:   subscription. `engine/codex.py` drives `codex exec` on a ChatGPT sign-in. The
325:   package deliberately imports no vendor SDK, to avoid metered billing.
326: - **Note for this team:** ArchPilot does not talk to opencode or the Meta API
327:   today. To drive it with muse-spark, add a third engine behind the same
328:   interface (`start / send / events / cancel / stop`, emitting `EngineEvent`s)
329:   that shells out to opencode. `engine/codex.py` is the closest template,
330:   because it also runs one process per turn and resumes by id. Codex has no
331:   PreToolUse hook, so its modes map onto its sandbox. An opencode engine would
332:   need an equivalent answer for the approval gate.
333: - Run with `uv sync`, then `systemctl --user enable --now archpilotd.service`.
334:   Config is in `~/.config/archpilot/config.toml`, and every key defaults
335:   (`DEFAULTS` in `src/archpilot/config.py`).
336: - The UI runs on `/usr/bin/python3`, not on the venv, because PyGObject is
337:   built for the system interpreter.
338: - Tests: `cd archpilot && .venv/bin/pytest -q`. vim.py, commands.py and
339:   policy.py have no GTK import, so they are tested headless.

341: ### 5.7 wa, the WhatsApp TUI (`whatsapp/`)
342: 
343: - Go, pure (`CGO_ENABLED=0`). Reads go straight to wacli's SQLite, read-only,
344:   with a schema probe and a CLI fallback. Writes go through `wacli`, delegated
345:   to a running `sync --follow` over its Unix socket (about 2.7 s, so the UI is
346:   optimistic). The measurements are in `whatsapp/docs/delegation-probe.md`.
347: - Install with `cd whatsapp && ./install.sh` or `make install` (to
348:   `~/.local/bin`). It needs wacli 0.18+, authenticated. `wa doctor` reports
349:   what it can see.
350: - Config is in `~/.config/wa/config.toml` (watched), plus `overrides.toml`
351:   for `:set!`. The palette comes from the generated `whatsapp/theme.toml`.
352: - **Roadmap** (`docs/superpowers/specs/2026-09-08-wa-core-design.md`), six
353:   sub-projects:
354:   1. core: done.
355:   2. media: done.
356:   3. rich messages: reply, react, forward, revoke and star are done; polls,
357:      location and edit are not.
358:   4. management: contacts and the chat drawer are done; groups, channels and
359:      backfill are open.
360:   5. ai: **not started**.
361:   6. hooks: **not started**.
362: - Visual design decisions (pill caps, "half" bubble edges, SelectedFill,
363:   `theme.Readable` contrast) were chosen by screenshot. Do not relitigate them
364:   without looking. To see real pixels, use Xvfb + kitty (x11) + a private tmux
365:   server + a screenshot; `tmux capture-pane` cannot show images.
366: - Golden render tests are in `internal/ui/render/testdata`. Refresh them with
367:   `go test ./... -run TestGolden -update`, and read the diff before you commit.
368: - The `wa lock` password hides the interface only. It does not encrypt
369:   wacli's store.

453: ## 7. Traps, in one list
454: 
455: Each one has cost real time. Details are in the cheatsheet or the component
456: READMEs.
457: 
458: - `config ok` from Hyprland ≠ the config works.
459: - `eww reload` success ≠ the new config loaded.
460: - `gsettings set` with no session bus exits 0 and writes nothing, so wrap it in
461:   `dbus-run-session`. The same applies to reading and writing xfconf.
462: - The AUR is not reliable. `wallust` stopped building (upstream checksum), so
463:   there is a `cargo install --locked wallust` fallback step. AUR packages are
464:   installed one at a time, so one failure cannot take the others down. Do not
465:   use `wallust-git`: it is v4-alpha and rejects the v3 config.
466: - Installer steps run in **file order**. `after` is checked by a test, not
467:   topologically sorted. An empty `check` always counts as "to do".
468: - `pacman -Qqe` is not the install list. About 30 needed packages are
469:   installed only as dependencies.
470: - `wl-copy` stays resident, so never wait for it to exit.
471: - The first click after an eww panel maps can miss. The selftest warms up.
472: - A capture's clipboard write racing with an OCR text write is why OCR copies
473:   text only.
474: - The rule that floats every window at 1200x800 also catches overlay tools
475:   like flameshot. Exclude them.
476: - Tailscale's operator grant is per profile.
477: - Old copies of `setwall`, `rofi-paper` and `find_internal_audio` still sit in
478:   `/usr/bin`. `/usr/local/bin` shadows them, so `link-bin` must stay run.
