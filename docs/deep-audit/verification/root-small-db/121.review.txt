189-# Providers
190-
191-Using any LLM provider in OpenCode.
192-
193-OpenCode uses the [AI SDK](https://ai-sdk.dev/) and [Models.dev](https://models.dev) to support **75+ LLM providers** and it supports running local models.
194-
195-To add a provider you need to:
196-
197-1.  Add the API keys for the provider using the `/connect` command.
198-2.  Configure the provider in your OpenCode config.
199-
200----
201-
202-### [Credentials](#credentials)
203-
204-When you add a provider’s API keys with the `/connect` command, they are stored in `~/.local/share/opencode/auth.json`.
205-
206----
207-
208-### [Config](#config)
209-
210-You can customize the providers through the `provider` section in your OpenCode config.
211-
212----
213-
214-#### [Base URL](#base-url)
215-
216-You can customize the base URL for any provider by setting the `baseURL` option. This is useful when using proxy services or custom endpoints.
--
221:{  "$schema": "https://opencode.ai/config.json",  "provider": {    "anthropic": {      "options": {        "baseURL": "https://api.anthropic.com/v1"      }    }  }}
222-```
223-
224----
225-
226-#### [Hiding models](#hiding-models)
227-
228-You can hide specific models from the `/models` picker for a provider using the `blacklist` option. This is useful when a provider exposes models you don’t want to use or select.
229-
230-opencode.json
231-
232-```
233-{  "$schema": "https://opencode.ai/config.json",  "provider": {    "anthropic": {      "blacklist": ["claude-opus-4-20250514"]    }  }}
234-```
235-
236-The inverse `whitelist` option hides every model except the ones listed.
237-
238-opencode.json
239-
240-```
241-{  "$schema": "https://opencode.ai/config.json",  "provider": {    "anthropic": {      "whitelist": ["claude-sonnet-4-20250514"]    }  }}
242-```
243-
244:Both options take an array of model IDs — the same IDs shown in the `/models` picker.
245-
246--   `blacklist` removes the listed models from the picker.
247--   `whitelist` keeps only the listed models and hides the rest.
248--   You can combine them: `whitelist` narrows the set, then `blacklist` removes entries from it.

1155-##### [GitLab Duo Agent Platform (DAP) Workflow Models](#gitlab-duo-agent-platform-dap-workflow-models)
1156-
1157-DAP workflow models provide an alternative execution path that routes tool calls through GitLab’s Duo Workflow Service (DWS) instead of the standard agentic chat. When a `duo-workflow-*` model is selected, OpenCode will:
1158-
1159-1.  Discover available models from your GitLab namespace
1160-2.  Present a selection picker if multiple models are available
1161-3.  Cache the selected model to disk for fast subsequent startups
1162-4.  Route tool execution requests through OpenCode’s permission-gated tool system
1163-
1164-Available DAP workflow models follow the `duo-workflow-*` naming convention and are dynamically discovered from your GitLab instance.
