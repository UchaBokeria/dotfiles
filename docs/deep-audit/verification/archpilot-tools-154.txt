597: ## 11. Adding an opencode engine (plan for this team)
598: 
599: `opencode run` already has what an engine needs. Verified with `opencode run
600: --help` on opencode 1.18.32; the event shapes were **not** probed:
601: 
602: - `--format json` emits raw JSON events.
603: - `-s/--session <id>` or `-c` continue a session.
604: - `-m provider/model` picks the model, for example
605:   `meta-lucky/muse-spark-1.3`.
606: - `--variant` sets reasoning effort.
607: - `--agent <name>`, `--dir <cwd>` and `-f <file>` (attachments) exist.
608: - `--attach http://…` uses a running `opencode serve`.
609: - `--auto` auto-approves permissions. **Do not pass it**; it is the
610:   equivalent of Codex's bypass flag.
611: 
612: Steps (use `engine/codex.py` + `tests/test_codex.py` as the template; both are
613: one-process-per-turn and resume by id):
614: 
615: 1. **Probe first**, the way this project did for Claude and Codex. Run
616:    `opencode run --format json -m <model> "hi"` in a scratch dir. Record every
617:    event type, where the session id appears, and what a failure looks like
618:    (bad key, rate limit, network). Write them down like
619:    `docs/hook-contract.md` and `whatsapp/docs/delegation-probe.md`.
620: 2. `engine/opencode.py`: `OpencodeEngine` with the §5 interface.
621:    - Map events to `delta` / `message` / `tool` / `result` / `error`.
622:    - Put `usage` and `modelUsage.contextWindow` into the `result` raw so the
623:      context meter works.
624:    - Add a `thread_exists()` equivalent.
625: 3. `modes.py`:
626:    - `OPENCODE = "opencode"` in `ENGINE_CYCLE`.
627:    - an `opencode_argv()` builder.
628:    - a mode mapping (below).
629: 4. `session.py`:
630:    - `ensure_started` branch.
631:    - `resume_hint` (`opencode -s <id>`).
632:    - a field like `codex_thread` for the opencode session id.
633: 5. `persist.py`: save and load that id.
634: 6. `daemon.py`:
635:    - `_models_for`, `_default_model`, `_switch_engine` (fresh/restored
636:      logic).
637:    - The auth pre-flight in `snapshot()` is Claude-only; add an opencode
638:      check or skip it.
639: 7. `config.py`: an `[opencode]` section (binary, models, default_model,
640:    agent). `commands.py`: `ENGINES`. `problems.py`: rules for Meta/opencode
641:    error strings, **placed before** the generic Claude auth rule. `ui/theme.py`
642:    and `gtk_app.py`: an `engine-opencode` chip class and the tooltip text.
643: 8. **Safety decision (required).** opencode's tools do not pass through
644:    ArchPilot's PreToolUse hook. Options:
645:    1. Run an **ask-mode agent** whose permissions deny edit and bash.
646:    2. Write an opencode **plugin** hooking tool execution that calls
647:       `policy.classify()` and the daemon's `ask_permission` op. This reuses
648:       the whole gate and the widget approval UI, so it is the best option.
649:    3. Rely on opencode's `permission` config (`ask`/`deny`).
650: 
651:    Note that the repo's current `opencode.json` has `"*": "allow"`.
652:    Whichever you choose, fail closed.
653: 9. **Billing:** Meta keys are metered API keys (`MODEL_API_KEY*` fish
654:    universal vars). That deliberately departs from ArchPilot's "never
655:    metered" rule, so strip nothing, but document it.
656: 10. Tests: copy the fake-binary pattern from `tests/test_codex.py` /
657:     `tests/test_engine.py`, which drive a stub script emitting recorded
658:     JSON lines.

762: ## 14. Working rules and traps
763: 
764: - **Never `pkill -f archpilot` / `pgrep -f archpilot`** from an agent's
765:   shell. The pattern matches the agent's own command line and kills it
766:   (exit 144). Use `systemctl --user restart archpilotd`, `pkill -x`, or
767:   explicit PIDs.
768: - **A throwaway GTK probe needs its own `application_id`**, for example
769:   `dev.archpilot.probe.x`. Reusing `dev.archpilot.ui` hands activation to the
770:   running window, and the probe silently prints nothing. Load CSS yourself
771:   with `theme.css()`.
772: - Never pass `--bare` to `claude`: it forces `ANTHROPIC_API_KEY` (metered).
773:   `--mcp-config '{}'` is rejected; use `'{"mcpServers":{}}'`.
774: - `asyncio.start_unix_server` must not be used as `async with` for shutdown.
775:   `wait_closed()` blocks on the never-ending subscribe connections, so
776:   systemd would SIGKILL after 90 s. `serve()` closes subscribers explicitly.
777: - GTK3-era lessons still apply to CSS: no `line-height` or `caret-color` in
778:   GTK CSS, since either aborts the parse. Icon glyphs need
779:   `"Symbols Nerd Font"`.
780: - Use `git status --porcelain -uall` (not the default) whenever
781:   new-file detection matters.
782: - Before loading a plugin or changing the Hyprland config, read the Lua
783:   traps in `../docs/cheatsheet.md`.
784: - Commits in the parent repo: stage explicit paths, never `git add -A`. The
785:   repo is **public**, and ArchPilot's own auto-commits go into it. Write
786:   commit messages in the repo's style: `fix: <what now holds>`.
787: - Changing a keybind or command means updating `README.md` and
788:   `commands.KEYBINDINGS` (the `:help` source), and
789:   `../docs/cheatsheet.md` → "ArchPilot" if user-facing.

813: ## 16. Ambient triage
814: 
815: `archpilot-triage.timer` fires 10 minutes after login, then every 6 hours. It
816: runs `archpilot triage --notify`, which scans four checks:
817: 
818: - `pacnew`: `.pacnew`/`.pacsave` files under `/etc`.
819: - `failed-units`: failed units, system and user; urgent.
820: - `disk`: a filesystem ≥90 % full, urgent at ≥95 %.
821: - `docker`: ≥5 GB reclaimable.
822: 
823: An unchanged finding is re-notified only after 12 hours. Each finding carries
824: a ready prompt, so `archpilot triage --ask <key>` starts a new chat with it.
825: Those generated prompts are filtered out of history. The rice's
826: `blackwall-watch` runs its own, overlapping checks; the two are independent.
