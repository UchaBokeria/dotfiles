# ArchPilot handover

Written 2026-09-24 from a full read of the source, a live test run and
probes on the running machine. It covers everything in `archpilot/`, plus
the parts of the parent repo (`blackwall`, the Hyprland rice) that
ArchPilot touches. The parent repo has its own handover in `../handover.md`.

Where this file and `README.md` disagree, this file is right. §12 lists
the stale spots in the README and the code comments.

---

## 1. What it is

ArchPilot is a system-wide AI assistant for an Arch + Hyprland desktop. It
has four parts:

1. **`archpilotd`**: an asyncio daemon (systemd user unit). It owns the
   conversations, spawns the AI CLI, brokers approvals and sudo passwords, and
   auto-commits file changes.
2. **`archpilot-ui`**: a GTK4 window (class `dev.archpilot.ui`) with a
   vim-modal prompt and a chat transcript, opened with `SUPER+~`.
3. **`archpilot`**: a CLI used by keybinds, waybar and scripts. It talks to
   the daemon.
4. **`hooks/pretooluse.py`**: the safety gate that every tool call of the
   AI goes through.

The model never runs inside ArchPilot. The daemon drives an external CLI
through a swappable **engine**:

| Engine | CLI | Billing path | Process model |
|---|---|---|---|
| `claude` (default) | `claude -p` (Claude Code, 2.1.281 here) | Claude subscription over OAuth. `ANTHROPIC_API_KEY` is stripped on purpose. | one long-lived child per conversation, stream-json on stdin/stdout |
| `codex` | `codex exec --json` (codex-cli 0.154 here) | ChatGPT sign-in. `OPENAI_API_KEY` / `CODEX_API_KEY` are stripped. | one process per turn, resumed by thread id |

The core design rule: **no vendor SDK is ever imported and no metered API is
ever used**. `pyproject.toml` has `dependencies = []`, so the whole project is
stdlib only.

> **For the opencode / Meta muse-spark team:** ArchPilot cannot talk to
> opencode or the Meta API today. §11 is a concrete plan for adding an
> `opencode` engine. Using a Meta API key breaks the "never metered" rule
> above, so decide that deliberately.
