## 5. The engines in detail

### Claude (`modes.build_argv`)

```
claude -p --model <m> (--session-id <uuid> | --resume <uuid>)
  --input-format stream-json --output-format stream-json --include-partial-messages --verbose
  --append-system-prompt "<machine block from context/rice.py>\n\n<SYSTEM_PROMPT_SUFFIX>"
  --settings $XDG_RUNTIME_DIR/archpilot-settings/<mode>.json
  [--effort low|medium|high|xhigh|max]
  --setting-sources ''                         # ignore the user's own settings/hooks
  --strict-mcp-config --mcp-config '{"mcpServers":{}}'   # or only the servers named in [mcp] servers
  ask:    --permission-mode manual --disallowedTools Write Edit NotebookEdit
  action: --permission-mode acceptEdits
```

- The session id is generated by ArchPilot (uuid4), so every conversation
  can be resumed in a terminal: `cd <cwd> && claude --resume <id>`. The
  default cwd is `archpilot/` itself (`paths.BASE_DIR`).
- Transcripts live in `~/.claude/projects/<slug>/<id>.jsonl`. The slug is the
  cwd with `/` and `.` both replaced by `-`.
- The child is held open across turns, so prompt caching hits the system
  prompt.
- `STREAM_LIMIT` is 32 MB, because asyncio's 64 KB line limit broke on
  base64 screenshots. stderr is drained continuously (last 40 lines kept) so
  a full pipe cannot wedge the child.
- `cancel()` sends SIGTERM, waits 0.7 s, then SIGKILL. `stop()` closes stdin
  and waits 5 s.
- Slash commands (`/compact`, skills) work: `--disable-slash-commands` is
  deliberately absent.
- The model cycle is `haiku → sonnet → opus`. `:fable` is also accepted as a
  directive or via `:model`. Effort cycles `low … max`.
- Rate limits: `rate_limit_event` reports reset times only (5h / weekly /
  weekly_opus). The meters show time remaining in each window, not quota
  used, because Claude Code does not report quota.

### Codex (`modes.codex_argv`, `engine/codex.py`)

```
new:    codex exec --sandbox <read-only|workspace-write> -C <cwd> --json --skip-git-repo-check [-m M] [-c model_reasoning_effort="E"] -
resume: codex exec resume -c sandbox_mode="<…>" --json --skip-git-repo-check [-m M] [-c …] <thread> -
```

- The prompt arrives on stdin (`-`). Codex has no
  `--append-system-prompt`, so the instructions ride in the **first**
  message of a thread inside `<instructions>`.
- **Mode is the sandbox**, because Codex has no PreToolUse hook. **ask** is
  `read-only`. **action** is `workspace-write`, which can write inside the
  session cwd **with no approval prompt**. The flag
  `--dangerously-bypass-approvals-and-sandbox` is never passed.
- The thread id is adopted only after a turn **completes**. A thread whose
  first turn failed is abandoned and started again.
- Models come from `~/.codex/models_cache.json` (visibility `list`), with
  `model` from `~/.codex/config.toml` first, or from `[codex] models` in the
  config. The list is cached for the daemon's life.
- Effort is clamped to the model's `supported_reasoning_levels`. `max`
  becomes `xhigh` where that is the model's ceiling.
- Resume in a terminal with `codex resume <thread>`.

### The engine interface (what a third engine must implement)

`start()`, `send(text)`, `events()` (an async iterator of
`EngineEvent(kind, text, raw)`), `cancel()`, `stop()`, `running` (property),
and `stderr_tail` (property).

Event kinds the daemon understands:

- `delta` and `message`: text.
- `tool`: `text` holds a ready activity line, or `raw.message.content`
  holds a tool_use block.
- `rate_limit`: `raw.rate_limit_info`.
- `result`: ends the turn. `raw.usage` and `raw.modelUsage[*].contextWindow`
  are read for the context meter. `is_error` / `subtype` mean failure.
- `error`: ends the turn as a crash. The text is classified.
- `system`.

## 7. The GTK window (`ui/gtk_app.py`)

- A plain toplevel (not layer-shell), 900 px wide, 176–560 px tall (700 with
  the `:` panel open). It resizes itself to its content through `hyprctl
  dispatch 'hl.dsp.window.resize({...})'`, which is already Lua syntax. The
  Hyprland rule in `../hypr/lua/rules.lua` gives it float, center and 900x176.
- The prompt is a **Gtk.Label rendered from `VimBuffer`**, not an Entry. vim
  owns the text and cursor, and the block cursor is a Pango span. The one real
  Entry is the password field.
- The key controller runs in the **CAPTURE** phase. No button can take focus
  (`set_can_focus(False)`); otherwise Space and Enter activate buttons.
- Regions: `Tab` toggles input ↔ chat. In the chat:
  - `j`/`k` select a message, `gg`/`G` jump.
  - `y` copies the message, `u` rewinds to it.
  - `ctrl-d`/`ctrl-u` scroll.
  - `ZZ` closes the window.
  - `i`, `a` or Esc go back to the input.
- Chords that change settings (all are also clickable chips):

  | Keys | Changes |
  |---|---|
  | `shift+tab` | mode |
  | `ctrl+tab` | model |
  | `alt+tab` | effort |
  | `ctrl+alt+tab` | engine |

- Tab and window commands:
  - `alt+1..9` jumps to a tab; `gt`/`gT` go to the next/previous tab.
  - `ctrl-t` starts a new chat (daemon `OP_NEW`).
  - `ctrl-w` closes the tab.
  - `ctrl-s` opens the sessions picker (rofi).
  - `ctrl-c` stops the running turn, and so does **Esc Esc** within 0.7 s
    while thinking, which also puts the prompt back in the input.
- `super+enter` runs the first live action of the selected message, or of
  the newest message with one.
- **History search** (`ctrl-h`) opens at the top:
  - Typing filters over prompts from **all** Claude Code transcripts on the
    machine (the last 96 KB of each of the newest 120 files, cached by
    mtime+size).
  - `Tab` switches between the query and the results. `j`/`k` move through
    results.
  - `Enter` **opens that conversation** as a live resumable session
    (`OP_OPEN_SESSION`).
  - `r` renames a chat; names are stored in `titles.json`.
- **`:` command line** (normal mode):
  - `:new`, `:model`, `:effort`, `:mode`, `:engine`, `:history`,
    `:sessions`.
  - `:export [path]` (default `~/archpilot-<stamp>.md`), `:copy`.
  - `:mcp <server> [on|off]`, which applies to sessions started afterwards.
  - `:cancel`, `:tabnew`, `:tabclose`, `:quit`, `:help`.
  - Aliases work, and so do unambiguous prefixes. Tab completes.
  - Parsing lives in `commands.py`, which also holds the `KEYBINDINGS`
    table shown by `:help`.
- **vim** (`vim.py`, 1,110 lines, no GTK):
  - motions `h j k l 0 ^ $ w W b B e E f F t T gg G`.
  - operators `d c y` with counts on either side; `dd cc yy D C Y`.
  - edits `x X s S p P r J ~`; undo/redo is per insert session.
  - visual `v`, `V` and block `ctrl-v`, including block `I`/`A`/`c`/`d`.
  - macros `q{reg}` … `q`, `@{reg}`, `@@`.
  - multicursor in the style of vim-visual-multi: `ctrl-n` for the next
    occurrence, `ctrl-up`/`ctrl-down` to add a cursor.
  - `ctrl-a` selects all. There are **no text objects** (`iw`, `ab`).
- Insert-mode keys:
  - `Enter` sends; `shift+enter` inserts a newline.
  - `up`/`down` on the first/last line walks through earlier prompts.
  - `ctrl-v` pastes; an image becomes an attachment
    (`$XDG_RUNTIME_DIR/archpilot-shots/paste-*.png`).
  - `ctrl-backspace` deletes the previous word.
- Attachments can also be dropped onto the window. They show as a strip of
  thumbnails above the input.
- Copying: every message has a copy button. Drag-selecting any text copies
  it to the clipboard **and** the primary selection. `wl-copy` is fired and
  never awaited, because waiting for it froze the UI.
- Panels:
  - **approval** (`y` approve / `x` deny).
  - **password** (a masked Entry).
  - **notice**: the yellow panel for a recognised Problem, with `L` to run
    the fix in a terminal, `R` to retry, Esc to dismiss. When the daemon is
    down it shows `systemctl --user restart archpilotd`.
  - **error**: a red line with the raw text, shown only when no Problem was
    recognised.
- Meters:
  - context (`ctx`), which turns amber at ≥75 %.
  - time left in the 5-hour limit window, amber at ≤15 % left.
  - the weekly reset, amber at ≤10 % left.
- **Theme**: CSS is built from the rice's tokens by importing
  `../theme/blackwall_theme` (stdlib) through `sys.path`. If that import
  fails, a local derivation from `eww/colors.scss` is used. A GFileMonitor on
  `eww/colors.scss` restyles the window live when the wallpaper changes. The
  window radius (22 px) must equal Hyprland `rounding`.
- Glass: `../hypr/lua/glass.lua` tags `dev.archpilot.ui` for hyprglass.
- The draft survives closing: `OP_DRAFT` on close-request, restored from the
  `draft` field of the first state.
