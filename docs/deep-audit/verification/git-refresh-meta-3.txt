fix: glass stopped working because a tag outlived the state that set it

`hl.window_rule({ match = { fullscreen = true }, tag = "+hyprglass_disabled" })`
looked like a free optimisation - a fullscreen window has no visible edge, so
why spend the GPU. But a tag is not a state: the window goes fullscreen once,
picks the tag up, leaves fullscreen, and keeps it forever.

So the glass degraded quietly, window by window, as things were fullscreened
over a session. Caught on this machine with hyprctl:

  kitty          fullscreen=0  tags=['hyprglass_disabled*', 'hyprglass_enabled*']
  google-chrome  fullscreen=0  tags=['hyprglass_disabled*']

Neither was fullscreen; chrome had been, for one video. Nothing else in the
repo tags chrome disabled - the only other disable rule is mpv|vlc|imv.

The rule is gone, with a comment saying why it must not come back. Verified: a
newly mapped kitty now carries hyprglass_enabled and nothing else. Windows that
were already poisoned keep the tag until they are re-mapped - Hyprland does not
drop a rule-derived tag on reload - so they need reopening once.
