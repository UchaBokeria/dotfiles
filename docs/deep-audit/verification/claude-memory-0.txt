metadata: 
  node_type: memory

  modified: 2026-08-23T20:07:40.396Z
---

When writing a throwaway GTK4 script to inspect ArchPilot's window, give it its
own `application_id`. Reusing `dev.archpilot.ui` (as `ArchPilotApp` hardcodes)
makes GTK treat the probe as a remote instance of the already-running widget:
`app.run([])` hands activation to that instance and returns 0 immediately, so
the probe prints **nothing at all** and looks like a silent failure.

**Why:** `Gtk.Application` deduplicates by application_id over D-Bus. Exit 0 with
no output is indistinguishable from a crashed callback, which wastes a debug
cycle.

**How to apply:** In probes use e.g. `Gtk.Application(application_id=
"dev.archpilot.probe.<what>")` and construct `ArchPilotWindow(app)` directly,
loading CSS via `theme.css()` yourself — `ArchPilotApp.do_activate` is what
normally installs the stylesheet, so a bare window renders unstyled.
Related: [[pkill-f-self-match-kills-the-shell]].

The blackwall rice has one source of truth for its look:
`~/.config/.dotfiles/blackwall/theme/blackwall_theme/tokens.py`. A generator
(`theme/blackwall-theme`) derives glass/rim/depth/radius tokens from wallust's
palette and writes a tokens file per surface. `scripts/setwall` runs it right
after `wallust run`.

**Why the generator exists:** wallust's templating has no colour arithmetic at
all - `lighten` errors with "unknown method", and `.rgb`/`.rgba`/`.red` render
empty. It can only emit raw palette entries, so anything derived (alpha, mix,
contrast correction) has to happen outside it.

**How to apply:** to change how the rice looks, edit `tokens.py` and re-run
`theme/blackwall-theme`. Never put a literal colour in waybar/eww/rofi/mako
config. Radii must come from the five-step scale (22/18/12/8/999) - GTK CSS
cannot hold a length in `@define-color`, so waybar and wlogout spell radii
literally, and `blackwall-theme --check` audits them. Tests:
`theme/run-tests`. Safety net: `scripts/blackwall-snapshot save|list|diff|restore`.

Two traps that cost real time: alpha-less formats (kitty, cava, tmux, nvim)
need `Colour.over(bg)` and not `.hex6`, which silently drops the alpha and
returns the colour at full strength; and kitty rejects `#RRGGBBAA` outright.
Related: [[blackwall-glass-needs-layerrules]].

name: blackwall-glass-needs-layerrules
description: "Frosted glass on waybar/rofi/mako needs a Hyprland layerrule, not just CSS alpha - and xray must be off"
metadata:
  type: project
---

In Hyprland, panels (waybar, rofi, mako, eww) are **layer-shell** surfaces, so
`windowrule` never matches them - they are matched by `layerrule` on their
namespace. Live namespaces here: `waybar`, `rofi`, `notifications` (mako),
`eww_calendar` / `eww_ios` / `eww_wifi`, `logout_dialog` (wlogout).

Glass needs three things together, and any one alone looks broken:

1. translucent background in the surface's own CSS (alpha on the *background*,
   never a compositor `opacity` rule - that fades text too),
2. `layerrule = blur on, match:namespace <ns>`,
3. `layerrule = xray off, match:namespace <ns>` - xray makes blur sample only
   the wallpaper and skip windows, so a panel over a terminal shows blurred
   wallpaper rather than the blurred terminal actually behind it.

Also set `layerrule = ignore_alpha 0.15-0.2`: waybar's window is transparent
except where modules paint, and without a threshold Hyprland blurs the whole
1890x62 rectangle and leaves a ghost band across the screen.

`layerrule` does **not** support `rounding` (Hyprland 0.56) - layer surfaces
round themselves in CSS, so the radius-mismatch trap only applies to real
windows. Related: [[blackwall-design-tokens]].

`./install` at the repo root is a doorway: it checks for Arch, refuses root,
offers to install rust, primes sudo once, builds `installer/` (ratatui) and
runs it. Everything the installer applies is data in `installer/data/`:
`packages.toml` (groups; core/fonts/theming required), `links.toml` (links,
copies, gsettings/xfconf values, `[[gap]]` for things with no source) and
`steps.toml` (ordered builds/services, each with a `check`). Configs that used
to live only in `~/.config` were adopted into `home/` in the repo.

**Why:** Ucha wants a fresh clone of `nuc` plus `./install` to give the exact
setup (2026-09-14), with nothing assumed, backups instead of overwrites, and
personal items skipped.

- A new script, config file, service or package in the rice needs a matching
  catalogue entry, or the next machine silently lacks it.
- `pacman -Qqe` is NOT the install list: 30 packages the rice needs (playerctl,
  wireplumber, procps-ng, util-linux, tesseract, go, python-gobject...) are
  installed here only as dependencies.

  Many rice files were untracked on 2026-09-14 (blackwall-autostart, glass.lua,
  18 whatsapp .go files); the TUI's preflight lists missing catalogue sources.
- `[[setting]]` is key/value only. Services and shell commands belong in steps,
  which have ordering, root and a check. xfconf values must be typed (bool/int).

  before the first Hyprland login or the Lua config raises.
- Test the TUI by running it in a kitty window with `--listen-on` +
  `allow_remote_control=yes`, driving it with `kitty @ send-text`, and grim.
  Use `env HOME=<empty dir>` to see what a fresh machine would get.

  backup writing onto the original (`expand("~")` returned a literal `~`, so
  `backup.join(<absolute path>)` threw the backup root away).
- `--dry-run --apply` lists exactly what the installer still thinks is to do on
  THIS machine; a to-do count that looks too high means a `check` is wrong, not
  that there is work. An empty `check` is always false.

`c2a` carries hard-coded internal hosts and two plaintext `sshpass` passwords.
It lives at `~/.local/bin/c2a` (mode 700) on the machine that needs it. It is
**not** in the blackwall repo: `.gitignore` blocks `scripts/c2a` and
`theme/tests/test_scripts.py::test_c2a_is_not_in_the_repo` fails if it comes
back, in the working tree or the index.

**Why:** it was tracked and committed from 2026-04-30 (commit 682bde8) in a
PUBLIC repo, so the passwords were world-readable for ~4.5 months. Keeping it
off PATH by hand was never the protection anyone thought it was - being
committed is what leaked it.

**How to apply:**
- Never re-add it, never link it from `scripts/link-bin`, never reference it
  from a catalogue entry as if it were a repo file.
- On 2026-09-19 the history was purged with `git filter-repo --path scripts/c2a
  --invert-paths`, and because PR refs (`refs/pull/1|2/head`) still served the
  blob after a force-push, the GitHub repo was **deleted and recreated** and the
  clean 139-commit history pushed back. `raw.githubusercontent.com` may keep
  serving an old SHA briefly - that is Fastly edge cache (`x-cache: HIT`), not
  retention; the API returns 422.
- A pre-rewrite bundle of the old history is at
  `~/blackwall-pre-rewrite-20260919-0039.bundle` (mode 600). It still contains
  the secret. Delete it once the credentials are rotated.
