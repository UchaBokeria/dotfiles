# WhatsApp source review, discovery pass

The non-UI Go source/test files are fully read by the parent, tracked in `whatsapp-coverage.jsonl`; all UI source/tests/golden fixtures are independently fully read in `whatsapp-ui-coverage.jsonl`. The initial Go inventory was 164 files / 42,318 lines. Desktop worker owns the surrounding docs/assets/integration. All findings are static unless otherwise specified. No real messages, contacts, store databases, account state or clipboard data are accessed by this review, and no client commands were run.

## Foundations read

`domain` deliberately has no I/O or imports of other project packages. JIDs preserve wire user/server/device identities but provide display forms; messages distinguish canonical ChatJID from StoredChatJID so LID folding can present one conversation without addressing wacli operations to the wrong stored row. Reactions are folded onto their target; media captions become body fallback; contact aliases win over names. Live events are described as hints for authoritative-store rereads rather than the sole message record. Receipts carry batches and participant identity.

`config` embeds default TOML, overlays authored config then machine overrides, explicitly merges keymaps, warns on unknown settings across versions but fails on syntax and invalid action names. This balances configurable evolution with visible failures. Reflection drives :set and settings completion from TOML-tagged fields, including custom duration/byte-size leaves. Action names go through one registry used by validation, picker and execution; empty/nil/duplicate actions fail during registration rather than at the eventual keypress. Action mode metadata filters listings; execution mode enforcement must be checked in UI/engine call sites.

The shape language is explicit: capsule half-circles match tmux/Waybar, a unified cell-spacing Layout avoids arbitrary margins/gaps, and which-key makes modal sequences discoverable. Test defaults explicitly match the owner's Neovim timeout=300ms, scrolloff=10, Space leader, smartcase/ignorecase and unnamedplus clipboard. This is continuity of interaction habits across desktop applications, not only a shared palette.

`wacli.Client` centralizes CLI JSON envelope decoding, per-invocation deadlines, global account/store flags, installed-bin lookup and error translation. SendText/SendFile share a mutex; optimistic UI is expected to hide delegation latency. Calls deliberately omit --lock-wait because prior measurements found it added latency before delegation. Post-send wait is configurable because the persistent sync process can answer retries. Human pairing deliberately bypasses JSON so a QR can display, but audit does not invoke it. Doctor is explicitly unsafe as a startup poll because it takes the lock and can starve sync. Store-read and daemon implementations remain pending to check these contracts end-to-end.

## Initial findings/questions

- **W-001 — XDG intent and path implementation diverge.** `internal/xdgpath/xdgpath.go:3-6` says :set! overrides belong under state; `Overrides()` at line 44 returns ConfigDir/overrides.toml. Lock, daemon, receipt and sent-quote records do use StateDir. Overrides are not inherently secret, so this is an ownership/documentation mismatch rather than proof of credential exposure.
- **W-002 — Persistent overrides do not preserve nested tables generally.** `config/path.go` exposes nested `ui.layout.*`; `persist.go:85-92` flattens only one map level. A later :set! after a nested layout override can turn that nested map into a string instead of keeping its leaf assignments. Current tests cover flat ui/lock scalar fields and do not cover preservation of nested ui.layout. Static call-path concern; no persisted user config was changed.
- **W-003 — Literal inference can change a string's TOML type.** `persist.go:136-143` emits true/false and integer-shaped values bare without consulting the field type. A string setting containing `2006`, `true`, or similar can validate through Config.Set but serialize as integer/bool. Tests cover a date-time string with punctuation, not numeric-only strings. Decoder behavior still needs a pure isolated verification before treating this as a reproduced failure.
- **W-004 — Atomic rename and multiprocess merge are separate properties.** Persist uses a fixed `<file>.tmp` and no lock; existing overrides are read then rewritten. Concurrent clients can overwrite each other's changes or race on the temporary path despite single-writer crash protection. Directory/file modes are 0755/0644, unlike 0700 directory setup elsewhere; those files are settings, not lock credentials.
- **W-005 — Read architecture comments as boundaries to verify.** `wacli/client.go:1` says it is the only subprocess package, but external media/clipboard helpers and daemon management are known product features; later reads must distinguish “only WhatsApp mutations” from “only subprocesses.” `domain.MediaRef.Downloaded()` checks nonempty metadata, not file existence; callers/cache validation must establish whether a deleted file can still be considered downloaded.
- **W-006 — Bounded errors can still contain content.** Wacli error strings include the full command arguments (`wacli/errors.go:49-53`) and timeout errors do likewise (`client.go:108-110`). For send commands those arguments include message/caption text. Check downstream logs, UI diagnostics, crash reporting and lock-screen behavior before asserting message text never leaves its display context.
- **W-007 — Startup order contradicts a lock-safety comment.** `cmd/wa/main.go:217-230` starts/adopts sync, then line 265 calls linkedAccount, whose lines 497-498 claim it runs before sync starts because Doctor takes the store lock. The current order is the reverse. Preflight also calls Doctor before adoption; existing external-sync compatibility needs a real-binary contract check. The code mismatch is confirmed; account lookup latency/failure is not reproduced here.
- **W-008 — Dropped events preserve message rows, not every UI fact.** `live/live.go:3-6` promises dropped events cost only latency, while `store/receipts.go:15-19` explicitly says receipt state exists only in webhook events until wa records it. The shared bounded channel drops oldest events indiscriminately. A receipt dropped before UI recording cannot be reconstructed from message rows or polling; delivery ticks can remain stale. This concerns advisory receipt state, not loss of message bodies. Check UI event routing before finalizing the complete consequence.
- **W-009 — Adopted webhook identity is recovered but not rebound.** Daemon.Start restores old Port/Secret on adoption (`daemon.go:119-122`), but main always creates a new listener/secret first and feeds that new Webhook into Merge (`main.go:201-246`). It does not start a receiver on recovered port or change the adopted sync's webhook endpoint. Polling still notices store growth, but receipt/presence fast paths can be unavailable to the adopting client. The daemon unit tests check restored getters; they do not run this top-level integration.
- **W-010 — UI lock is deliberately not storage encryption.** `lock/lock.go:3-10` states the boundary plainly; same-user processes can still read the store. Verifiers use salted Argon2id and live in state at 0600. Verify consumes stored cost parameters without validating nonzero/minimum/bounded values (`:141-144`); malformed verifier behavior needs a controlled pure verification. Do not represent the UI gate as a disk-data protection feature.
- **W-011 — Process liveness is weaker than identity.** State stores PID, owner PID and StartedAt, but Alive/OwnerAlive use signal 0 only (`daemon/state.go:61-84`); takeover later sends SIGTERM to that numeric PID (`lockgate.go:122-126`). No process start-time/executable check is visible. Stale PID reuse can therefore invalidate the intended ownership proof. No real process was signaled by the audit.
- **W-012 — Empty inner delimiters normalize into a nonempty range (isolated reproduction).** `vim/textobj.go:161-167` represents an empty body with From=1, To=0, Exclusive; `Span.Normalised()` reverses those endpoints. In an audit-only pure-source copy, deleting the inner body of `()` returned text `"("` and left `")"`. This confirms a low-level editing contract failure without opening wa or accessing a real draft. Source hashes, probe and exact output: `verification/wa-vim/` and `verification/wa-vim-result.txt`.
- **W-013 — Macro expansion resolves mode-changing keys too early (isolated reproduction).** `vim/engine.go:548-553` resolves all macro keys into a batch before its caller can apply the first action. A copied-source probe storing `iX<Esc>` returns only `mode.insert`, zero literal characters, with engine still NORMAL before caller application. Ordinary typed keys allow UI mode updates between Feed calls; this batch path does not. Existing tests replay deletes and simple actions, not an insert/change-mode macro. Full UI integration still needs reading, but the pure engine behavior is reproduced.

The full modal-engine source/tests are now read. Counts, operators, text objects, register/clipboard integration, macro depth limiting, prompt history and completion, per-draft linear undo and discoverability are intentionally separate from WhatsApp state. There are nuanced parity gaps to keep in mind: text positions are runes, not grapheme clusters; repeated edits store resolved operation metadata rather than a complete inserted-text change; unbind leaves trie child nodes that can keep a prefix apparently ambiguous. These are source facts/questions for later UI tracing, not blanket claims that every Vim behavior is absent.

## Media, clipboard and storage pass

All media and clipboard source/tests are now fully read. The older half-block-only package comment remains, while the actual implementation also has Kitty Unicode placeholder graphics. Its design solves an observed tmux placement problem: text placeholders stay in pane geometry while image placements directly tied to the outer cursor did not. Disk PNG caching and a single synchronized terminal writer avoid discarded/deduplicated frames losing image or clipboard commands. Downloads use wacli read-only output and a per-message staging directory, then rename to a stable ID-based cache file; optional ffmpeg produces actual samples/first frames rather than decorative fake waveforms. Missing optional tools degrade a specific preview feature.

- **W-014 — OSC52 forwarding misclassifies tmux external mode.** `clipboard/clipboard.go:113-121` treats both on and external as accepting application OSC52, suppressing the passthrough wrapper. The installed tmux manual (groff lines 4510–4539 after unescaping hyphens) and [upstream manual](https://man.openbsd.org/tmux#set-clipboard) distinguish application acceptance in on from external. Live default server returns external; source has no overriding set-clipboard assignment. Local wl-copy is preferred, so this does not establish that ordinary local copies fail; the no-helper/SSH fallback is the affected source path. No clipboard payload was read or written by this audit.
- **W-015 — Pixel graphics assume a shared filesystem without proving one.** `media/kitty.go:53-77` enables by terminal environment, and `KittyTransmitFile` always uses t=f. The [Kitty protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/#remote-client) distinguishes local file transfer from direct chunked pixel transfer for remote clients. A remote process announcing Kitty can therefore select a path the local terminal cannot read. The helper does not query filesystem sharing, use SSH context or process terminal replies (q=2). Source-level portability limit; remote image rendering was not exercised.
- **W-016 — Disk derivative caches can outlive changed source bytes.** Preview's in-memory key includes file size/mtime, but `Renderer.frame` names its PNG from path alone (`preview.go:203-206`), and KittyPNG uses path+pixel limit (`kitty.go:108-112`). Replacing a file at the same path can retain an old derivative despite invalidating the outer render key. Reuse tests cover unchanged input, not replacement. Cache ownership and multi-client fixed-temp-path races remain explicit design limitations.
- **W-017 — Half-block alpha compositing applies alpha twice.** `thumbnail.go:123-132` gets RGBA() values then multiplies channels by alpha again before adding grey. The installed Go image/color interface explicitly specifies premultiplied channels. This can darken partially transparent sticker pixels; fully opaque test images do not cover the branch. Source/API comparison, not a live visual reproduction.
- **W-018 — Text-preview acceptance does not sanitize terminal controls.** `preview.go:313-326` checks NUL and sparse control-byte ratio, despite its UTF-8 comment; it does not validate UTF-8 or strip ESC. The UI worker traced preview lines directly through bubble rendering, whose ANSI width helpers preserve arbitrary CSI/OSC/DCS/APC. Thus a mostly printable document can carry active terminal control sequences through the preview path. No control payload was emitted during the audit. See `whatsapp-ui.md` for exact downstream locators and malformed-CSI handling.

Storage first reads confirm the intended fast-path architecture: database connections use mode=ro and bound SQL parameters; keyset pagination uses timestamp+rowid to avoid same-second duplication; FTS syntax is quoted, schema probing falls back to wacli, and canonical LID display identity is kept separate from stored command identity. The complete SQLite/CLI adapters and their test contracts are still being reconciled. Polling only observes max-row/time change, so it is not a general change-data-capture feed for in-place edits, receipts or every chat flag.

The daemon implements useful safeguards: delegated command allowlist, serialized lock handover, refusal to stop another still-open client's sync, restart after a failed lock-requiring operation, readiness based on dialing the actual delegation socket, and polling underneath the webhook. Tests use temporary sockets and sleep children to specify these behaviors. They are meaningful unit contracts but do not establish top-level startup ordering or recovered-webhook integration. `pause()` can wait up to 13 seconds and returns nil even if release did not occur; supervisor/Stop each call a form of process Wait, so shutdown races require additional scrutiny.

## Store and palette reconciliation

All store and theme Go source/tests and the captured data-free schema are now read. The fast path is intentionally read-only, while owner-authored aliases and receipts live in small advisory side files. Message queries use bound values; FTS punctuation is quoted. Schema tests manufacture an older version number on today's schema rather than supplying an actual historical schema, which limits the compatibility evidence.

- **W-019 — Schema admission checks fewer objects than queries require.** `store/probe.go` checks three tables but `sqlite.go:120–122,281` reads contact system_name/first_name and message media_unavailable_at without checking them; queries also join groups, contact_aliases and group_participants. A lower migration number can pass admission with one of those objects missing, then fail direct queries instead of selecting the promised CLI fallback. Existing missing-column test removes unread_count, which is on the checked list. Source-confirmed admission gap; no real account database was opened.
- **W-020 — Reaction folding is input-order-dependent despite newest-first queries.** `sqlite.go:309–323` defaults to descending time/rowid before `foldReactions`; that function processes reactions in input order, replacing the prior sender reaction without comparing At. Thus an older reaction processed later can replace a newer change or undo removal. Ascending queries do not have that reversal. Existing replacement tests supply old then new, so they do not specify the default SQL order. Static end-to-end ordering proof, not a live send experiment.
- **W-021 — CLI fallback has a narrower feature contract.** `store/cli.go` implements the interface but omits ChatFilter.Tag and several Query fields (Browse, Kinds, HasLink, FromMe); empty-text browse returns nothing. Canonical LID folding and SQLite quote/receipt augmentation are also not reproduced by this adapter. Falling back preserves basic access rather than feature equivalence; interface satisfaction tests alone do not establish parity.
- **W-022 — Valid JSON null defeats advisory-log tolerance.** Both log constructors accept JSON null as successful unmarshal and leave entries nil; the next valid Record assigns into a nil map. Tests cover malformed JSON/missing files, not null. This contradicts the stated worst-case loss of only a quote/tick. Static Go map contract; no owner state touched.
- **W-023 — Failed advisory saves clear retry state early.** QuoteLog.Save and ReceiptLog.Save clear dirty before MkdirAll/WriteFile/Rename. A failed write is reported but later Save with no new Record returns success without retrying the unsaved entries. Fixed temporary names and absent cross-process merge also mean simultaneous clients can lose independent updates. The disk is presently near full (see machine report), but no actual write failure was induced.

The theme has a deliberate shared vocabulary: pill caps are the exact tmux/Waybar glyph family; glass removes full-width backgrounds while retaining filled content bubbles; icon families have Nerd/unicode/ASCII fallbacks, and generation counters invalidate palette-dependent renders. Named role overrides reject misspellings and invalid opaque hex. Wallpaper derivation is a separate fallback path from generated token palettes, so it does not guarantee identical status hues. Source detail: wallustPaths says first parseable file wins, but FromWallpaper returns the first readable file's parse error immediately; a malformed preferred cache prevents trying lower-priority caches. Cursor uses first nonempty rather than hex validation on this path. These are compatibility limits, not proof the current palette is malformed.

No global zero-new cycle has occurred. The separate UI report contains its own complete source coverage and findings; this is an audit, not an authorization to apply repairs or interact with chats.
