## Architecture and taste synthesis

The archive repeatedly trades implicit state for reviewable state: source-qualified credentials, one InitPlan shown before apply, versioned process identity, explicit model effort, typed unknown cost and a loop panel with uncertainty marks. Cheap execution and independent model-family judgment motivate the original relay; attribution failures then motivate capability constraints, task files and provenance; native models later remove relay overhead while preserving the harness route as fallback. These are documented project motives, not a claim every owner personally articulated every implementation detail.

The UI trajectory is functional before decorative: a plain monospaced table dashboard, a persistent keyboard config surface, then a progress-first loop panel with one accent, compact model/cost facts, selected diffs and honest ambiguity. Current React Sonata’s warm charcoal/orange, pill controls and four palettes (sonata-ui.md) are a later implementation identity; these archive documents do not establish a direct Blackwall wallpaper-token relationship. The source-facing shared taste is visible legibility, explicit state, reversible selection and predictable keyboard flow. Visual affinity alone is insufficient to infer a shared generator or deployment.
