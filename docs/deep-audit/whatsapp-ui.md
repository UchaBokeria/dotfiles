## Pass 1 UI routing and rendering contracts

Full reads so far: app/actions/events/log/composer/media-view and render ansi/wrap/bubble (62 of62, including all tests and three golden fixtures). Root model coordinates three focus sections and independent edit targets. Chat drafts carry their own buffer, undo and attachments; tab switches focus while Esc first leaves insert and then leaves draft editing. Raw terminal key batches are split into per-rune HandleKey calls, so ordinary paste/fast typing applies mode changes between feeds. Macros instead arrive as already-resolved batches, described below.

Taste is concrete: pane separation by space and focus accent rather than heavy dividing rules; margins/gaps from one cell-spacing config; inline file chip names attachments before sending; timestamp/reactions are transparent decoration beneath filled cards; one-line messages retain capsule silhouette while multiline cards use flat sides. Geometry is measured in grapheme clusters for wrapping, with a separate ANSI-aware column compositor. Help lists action descriptions, which-key narrows pending key sequences, backspace walks groups outward and Esc cancels. Small terminals switch to one pane rather than cramming both.

- **W-006 enhancement — send errors persist unredacted in in-memory log.** sendFail at `app.go:631` calls setError with the backend error; setError (`:1624`) records it through Log.Errorf. Log holds500 entries under a mutex (`logbuf.go:15`, `:53`), while :log copies text into the overlay (`app.go:1594`). Backend command arguments can therefore appear in status and log. Status expires after12 seconds; log retains entries until evicted/process exit. Lock View chooses lockScreen before overlay/body (`app.go:1338`), so it hides those contents while locked, but does not erase them. No disk-log sink established by this UI read.
- **W-008 enhancement — receipt persistence occurs only after event consumption.** `events.go:20-54` records receipt batches and saves the receipt log after the app dequeues the event. Subsequent ordinary event/poll refresh rereads message rows and cannot recreate an event never recorded. Source's blanket hint-only/drop-safe comment above applyEvent is false for receipt state. Presence events are deliberately ignored as a future subproject.
- **W-013 enhancement — UI does not repair macro pre-resolution.** routeKey (`app.go:862`) calls runResolved(engine.Feed(k)); runResolved (`:1011`) applies the returned slice in order. mode.insert changes engine only when its action is applied in `actions.go:140`; there is no replay of remaining raw macro keys after that change. The parent's isolated pure-engine reproduction therefore remains a full UI integration consequence.
- **WUI-001 — delayed failed send can overwrite another chat's current draft.** sendFailMsg carries localID/text/error but no chat/draft identity (`app.go:236`); handler marks current pane and calls composer.Restore(m.text) (`:631`). Restore overwrites current draft (`composer.go:133`). A failure from chat A after switching to B can replace B's unsent text with A's text. Even within A, a newer in-progress draft can be overwritten after an earlier send fails. Source only; test coverage not yet read.
- **WUI-002 — attachment failure loses retry attachment context.** send clears attachment list before taking/clearing the draft (`actions.go:1060`); sendFiles failure returns caption only (`:1498`), and failure handler restores text only. Failed file path(s), partial batch successes and reply target are not restored into draft. A retry needs reattachment and risks duplicating files already sent before the batch failed. Source only.
- **WUI-003 — terminal control text is preserved on preview output path.** mediaView returns Preview.Lines unchanged (`mediaview.go:82`); bubble bodyLines appends those strings (`render/bubble.go:360`); Pad/Truncate use StripEscapes only to measure, returning/copying escape strings rather than sanitizing them (`render/wrap.go:159`, `render/ansi.go:230`). Therefore a document preview accepted as text upstream can carry arbitrary OSC/CSI/DCS/APC into rendered output. Legitimate authored graphics and OSC8 require preservation, but untrusted document text needs a distinct boundary. No payload execution attempted.
- **WUI-004 — malformed CSI can exceed slice bounds in column compositor.** skipEscape's CSI branch returns j+1 even when no terminating letter exists (`render/ansi.go:57-62`). TakeColumns/DropColumns then slice runes[i:end] without clamping (`:239`, `:266`). A malformed terminal escape entering those paths can panic rather than degrade to text. Static candidate; no execution/probe.

## Pass 3 asynchronous boundaries

- **WUI-011 — timeout resolution does not return/drain scheduled work.** `app.go:722-724` calls runResolved(engine.Timeout()) then returns nil, ignoring its returned command and omitting takeCmd. Normal HandleKey wraps routeKey with withQueued. A custom ambiguous binding that resolves to a queued network action on timeout is drained by apply into runResolved's returned tea.Cmd and then discarded permanently; the timer path is not equivalent to normal dispatch. It also bypasses routeKey's lock guard; idle-lock behavior of a pending action deserves explicit isolation. Default <leader>i timeout is synchronous quickfix toggle, limiting the default visible symptom. No timer/client execution.
- **WUI-012 — Enter on undownloaded attachment queues download then reports failure to find it immediately.** openMedia (`mediaview.go:133-145`) calls downloadMedia, now asynchronous, then immediately asks localPath and returns "downloaded, but no local file appeared". downloadedMsg only invalidates pane/sets status (`app.go:670-676`), with no deferred opener. First Enter can therefore show this misleading error and download; a second Enter after completion is needed to open. Existing mouse test explicitly tolerates the error and checks only that the caption was not copied.
- **WUI-013 — bulk download status counts unattempted work as success and can lose failure details.** `mediaview.go:220-245` breaks on expired five-minute context but computes success as total jobs minus explicit failures, including jobs never attempted. The all-failed branch returns statusMsg without the collected failed strings, even while directing the user to :log; only downloadedMsg branch logs those reasons. Its "every attachment" action iterates loaded pane messages only (`:188`), and bypasses the single-file expiry/maxDownload checks. These are source behavior contracts, with no downloads attempted.
- **WUI-014 — live refresh retains stale search indexes.** MessagePane.Search stores numeric indexes (`messagepane.go:505-507`); Refresh replaces/reindexes message slice (`:274-276`) without recomputing searchMatches. LoadOlder prepends without recalculating them too. n/N can jump to a different message after prepend/refresh while MatchCount describes the previous set. selectIndex bounds-checks, so this observation is incorrect navigation/stale count rather than an established panic.

A broader identity caveat reinforces WUI008: receipt UI application (`events.go:35-42`) ignores ev.Chat when applying IDs; fetcher.seen (`fetcher.go:84-90`) likewise deduplicates by ID alone. Finder explicitly models ID as per-chat. Parent owns the persistent receipt/cache modules and should assess the shared identity contract before assigning impact.

Third pass added WUI011-014; this is not a zero-new pass. All findings remain static source observations, with live account/data acceptance deliberately unattempted.
