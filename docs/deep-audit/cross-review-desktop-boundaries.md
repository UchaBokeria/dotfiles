## BDR003 — Independent WhatsApp instances reuse the same terminal-global image namespace

`whatsapp/internal/ui/graphics.go:47–48` initializes each new graphics instance with nextID1. Lines100–115 allocate IDs only inside that instance's mutex/map; lines119–126 transmit and create virtual placement using the allocated numeric ID. `whatsapp/internal/media/kitty.go:142–144` passes that ID as explicit i= in the terminal command. In contrast, the new full browser viewer uses a PID-derived base and alternating owned IDs (`browser/pane/desktop.py:31,47–51`) and removes only its previous/final ID (:51,143); the page patch similarly replaces broad deletion with selected-ID deletion.

The [Kitty protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/#display-images-on-screen) states that retransmitting a specific ID replaces its existing image and placements. Its Unicode-placeholder section explicitly identifies image IDs as a global namespace, and its image-number section supplies a separate allocation mechanism for sharing a terminal. Therefore two graphics-enabled WhatsApp instances displayed through sibling tmux panes in the same outer Kitty window can both transmit i=1 and replace each other's image data/virtual placement rather than retaining pane ownership. A mutex within one instance cannot resolve that boundary. This is a source/protocol composition finding, not observed native flicker or proof that the installed dirty WhatsApp binary has identical code. It extends the already documented broad graphics cleanup limitation with a distinct allocation collision. No second application was opened and no graphics protocol was emitted.

A related precision limit: `graphics.Clear:131–135`/`KittyDeleteAll:194–197` use d=A, and its own comment claims ownership-specific cleanup. The protocol describes broad visible-placement deletion but separately says real displays drawn over Unicode placeholders are not protocol placements. Do not casually turn “delete all” into a proven claim that every sibling virtual browser picture is erased: the terminal's actual virtual-placement/data behavior would need matching implementation evidence or owner-authorized acceptance. The deterministic same-ID transmission collision above does not depend on that uncertain cleanup premise.
