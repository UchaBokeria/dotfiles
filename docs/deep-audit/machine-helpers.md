## Lifecycle and intent

**MH001 — Sonata deployment treats the running install as a release, separate from development.** `~/.local/share/sonata-ops/switch.sh:9–20,345–386` builds a detached Git worktree under sonata-releases, validates generated files and commit identity, then atomically flips the Bun package symlink. Existing live code is never the build directory. A journal saves prior symlink/config/statusline ownership; config changes get backups and validation in a temporary HOME. It requires at least2048MB free; server role requires clean dev, PC role permits dirty dev because it builds committed content. PC preflight fetches origin; optional server push is explicit. Successful deployment retains three recent release directories while protecting current/prior/live targets. These are source safeguards, not a deployment performed or rollback acceptance proved today.

**MH002 — Recovery and observable acceptance are part of deployment.** `switch.sh:241–285,488–545` restarts with an8192MB Node heap, waits for ready health, verifies the serving process's CLI path and heap, restores a paused budget table, and runs sonata-lights. Failure after symlink movement restores prior link/config, attempts restart or plain daemon start, preserves red-light evidence, then notifies. `sonata-lights.sh:43–105` checks package/command/commit/process identity, HTTP health latency, console/dashboard/statusline, limits/doctor, optional budget, OOM protection and sampled CPU after settling. Existing doctor FAIL categories are excluded from new-build lights (`switch.sh:385–387`); all-green means those scoped checks, with inherited exclusions and grey skipped checks, not absence of every existing problem. Litellm liveness uses curl without `-f`, so an HTTP error response can still pass its transport check (`sonata-lights.sh:55`).

**MH003 — The watchdog intentionally distinguishes slow from dead.** `router-watchdog.sh:25–33` treats only curl exit7 plus no live recorded router PID as down, so timeouts and busy health responses do not multiply routers. It requires two failures15s apart, respects an owned, live-PID deploy lock under15minutes old, then starts daemon and probes again. On healthy passes it protects router/LiteLLM OOM scores at-900 when allowed and follows Traefik IP changes by restarting a bridge (`:35–52`). A source comment records an unnoticed hour outage on2026-10-29 (`:2–5`); that is historical narrative. The deploy script refreshes its lock everyminute. Its dry-run is intentionally preflight/build-only, but still fetches, creates worktrees/state/logs and installs/builds dependencies; it is unsuitable for this read-only audit.

**MH004 — Memory pressure management preserves agent sessions by pausing them.** `~/.omnigent/bin/ram_guard.py:15–43,89–124,186–226` warns below4096MiB or PSI20%, pauses below2560MiB or tight swap plus low RAM, and resumes above4608MiB with PSI below10%. Polling is5s, pause cooldown20s. Only own UID and real executable tmux servers whose argv contains the omnigent terminal socket prefix are eligible; the full discovered descendants are SIGSTOPped. Largest RSS tree first, last paused first resumed; regular/default tmux is excluded. Stored process IDs do not include birth-time identity, so a stale manual resume can target a reused same-user PID; new descendants after freezing are not in the saved tree. These are source-derived edges, not signals sent. Alerts and earlyoom log forwarding are built in; the log is rejected when world-writable. Its status path reads source-defined memory/process state; run and resume write state or signal processes.

**MH005 — Omnigent relogin is narrowly triggered.** `omnigent-relogin.sh:6–19` checks an authenticated API and host-online status; only API401 or API200 with offline host triggers reading a private password source, CLI login, user-unit restart and alert. Unit restart happens even if login fails. `tg-send` reads a private environment source and places the Telegram request URL on curl's stdin config rather than argv. No recipient/token values are repeated here; no notification command was run.

**MH006 — The PC is a narrowly scoped Meta egress route.** `~/.local/share/meta-egress/meta-egress-proxy.ts:1–33` binds the VPN address on3128, allows exactly the Blackwall sourceIP and `api.meta.ai:443`, establishes IPv4 TCP, relays a CONNECT tunnel and drops it after5minutes idle. ## Cross-host working ergonomics

**MH007 — Claude state sync chooses continuity and no deletion.** `~/dev/cloud/sync-claude-state.py:2–21,41–45,92–114` maps local/prod project directory keys, syncs top-level JSONL chats plus one-level memory files over tar/SSH, newest-mtime-wins with2s skew and never deletes missing files. That is direct documentation of the intended same-resume-list workflow. It assumes transcripts have distinct session UUIDs and memory is one-fact-per-file. Concurrent edits of one memory file are overwritten by the newer timestamp, not merged; equal/near timestamps are ignored without hashes. `--dry-run` still creates the remote memory directory and appends the local log (`:93,112–114`). Neither dry-run nor live sync was executed.

**MH008 — Clipboard transfer preserves the local image and gives the remote agent a path.** `~/dev/cloud/bin/clip2cloud:2–23,78–139,153–175` documents why SSH/tmux cannot transfer clipboard image bytes directly. It accepts files/URI lists/raw binary clipboard/region capture; sanitizes basename to80shell-safe characters; refuses directories/empty data/plaintext and uploads over SSH/SCP with a100MBdefault cap. Region captures remain in screenshot history and PNG clipboard. Remote paths go to PRIMARY selection by default, preserving the image for a local chat; `--clip-path` explicitly replaces the regular clipboard. Remote upload directory old files are deleted after7days by default. Timestamp resolution is one second; two files with same sanitized basename, or names that sanitize/truncate identically, can overwrite in staging. Configured remote directory/retention enter a remote shell command directly, appropriate only as trusted configuration. Returned paths assume `/home/scriptkid` even if remote host is overridden.

**MH009 — Smart paste resolves stale sockets but retains a target fallback.** `kitty-smart-paste:22–58` tries the exported Kitty socket then newest matching abstract socket in /proc/net/unix. It targets KITTY_WINDOW_ID first, with recent:0 fallback; source comments explicitly fix earlier state:focused matching multipleOSwindows. Images upload through sibling clip2cloud, parse remote path and type it into the window; other content follows text paste. A failed explicit target can therefore type into another recently active window; upload-success notification follows send without requiring its success. Path extraction hardcodes the default clipboard directory, despite clip2cloud's directory override. Header says Ctrl+V, but current dotfiles bind the helper on Super+Shift+V; this is stale helper commentary. No clipboard was read or changed by this audit.

**MH011 — Frame identity and focus checks make computer control reviewable, with explicit limits.** Package server.py and coords.py require an existing screenshot frame, reject explicitly stale IDs, map per-axis scales and clamp coordinates to captured bounds. Window captures require active-workspace visibility but remain occlusion-based crops, not isolated application renders. hyprtree visibility uses activeWorkspace only and does not model active special workspace; mixed-scale/negative-origin/rotated monitor capture mapping needs controlled acceptance beyond today's single-monitor observation. Capture grabs the entire layout with grim and crops/scales via Pillow to1568px/1.15Mpixels; no capture was launched here.
