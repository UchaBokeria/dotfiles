## Browser bridge behavior

The Bun bridge stores registrations, pending accepts, tab snapshots, a11y trees, marks, grouping requests and network rules in memory. It binds loopback by default but allows a `BIND` override (`bin/bridge.ts:33`). The WebSocket hub forwards arbitrary named methods to the registered extension; it does not require an accepted pending session or authenticate the browser registration (`bin/bridge.ts:48`, `bin/bridge.ts:54`, `bin/bridge.ts:131`). Thus the Accept screen is a browser-choice interface, not an authorization boundary. Its revoke-by-closing-session hint has no corresponding revocation route or hub gate in this source (`browser-extension/accept.html:31`). This is a static property of the backup, not a claim about current running exposure.

Concurrent MCP clients each start their own numeric sequence at zero (`bin/cdp-mcp.ts:8`); bridge waiters are keyed only by that client-provided ID (`bin/bridge.ts:60`). Overlapping IDs can overwrite another client's waiter and misroute replies. Disconnect cleanup removes extension sockets but not waiter entries. SSE cancellation deletes the cancellation reason rather than the stored stream controller (`bin/bridge.ts:90`); failed enqueues are swallowed without removal. Expired group/mark requests are filtered on reads but retained in arrays.

Extension1.0.8 requests broad all-URL/tab/history/cookie/debugger permissions (`browser-extension/manifest.json:6`). It automatically uploads the entire tab list and the active HTTP(S) tab's a11y nodes on its tick (`browser-extension/background.js:22`, `browser-extension/background.js:150`). The a11y collector falls back to input values without filtering sensitive input types (`browser-extension/a11y.js:12`). This observation required no live page inspection.

Domain permissions default allow, ignore the write flag, and use hostnames only (`browser-extension/perm.js:16`). Evaluate checks caller-provided URL or an empty string; the MCP evaluate schema does not include a URL field (`browser-extension/cdp.js:120`, `bin/cdp-mcp.ts:64`). Click/fill/type funnel through evaluate without the actual tab URL. Snapshot, screenshot, upload, keypress and close do not consult that domain check. These are loose convenience controls, not a reliable per-tab permission boundary. The CDP event handler auto-accepts JavaScript dialogs (`browser-extension/cdp.js:48`). Idle detach time advances on every network/runtime event, so a busy page may remain attached despite no recent caller action (`browser-extension/cdp.js:36`).

Fill issues `Input.dispatchMouseEvent` with an empty argument object before selecting text (`browser-extension/cdp.js:158`); required protocol fields are absent. This was not executed or promoted to a verified live failure. Grouping and marking target exact URL matches across all tabs, so identical URLs can group unrelated session tabs; stale remembered group IDs are not recreated on failure.

## Panel and mobile workflow

The panel uses a dark rounded blue/purple visual system with gradient progress, hover-only copy slots, sticky composer, attachment chips, model/agent dropdowns, a full-height history drawer and browser-drive overlay (`browser-extension/panel.html:29`, `browser-extension/panel.html:101`, `browser-extension/panel.html:144`). The three icons are the same blue/purple orb on rounded black tiles at16/48/128 pixels.

Panel server settings include a hardcoded fallback login and are persisted through Chrome sync storage (`browser-extension/panel.js:3`). Values were not retained in this report. A narrow sanitizer initially missed the abbreviated credential field; that line was removed from the audit display, and abbreviated pwd/pass/clientsecret handling was added. No credential rotation or product change was performed.

The panel is a simple synchronous REST chat client, not a full mobile/realtime peer: it reads60 sessions and40 messages, filters only local title/slug history, truncates rendered message text to4000 characters but copies the full text, and posts a blocking message request (`browser-extension/panel.js:264`, `browser-extension/panel.js:280`, `browser-extension/panel.js:447`). Its EventSource listens to local bridge pending/accepted events only, not OpenCode session events. The context limit is the last configured model limit encountered, regardless of selected model (`browser-extension/panel.js:183`); displayed usage is therefore not established as accurate per-model context occupancy.

Send clears composer/attachments before network success and does not restore them after failure (`browser-extension/panel.js:382`). The disabled button is not an in-function busy guard: the Enter handler can invoke send again. No IME composition guard is shown (`browser-extension/panel.js:463`). File reads complete asynchronously with a20MiB per-file check and no aggregate/count limit; pending data is memory-only. Model and agent options are only applied while creating a session; posting follow-up parts sends neither (`browser-extension/panel.js:414`, `browser-extension/panel.js:447`). Session creation400 triggers a retry with default options, which can obscure a rejected choice.

The Fish rc helper reads service-file login configuration, may start the user service, finds the newest updated session under the current directory, prefixes its title and prints a mobile card (`bin/rc:4`, `bin/rc:33`). It does not identify the invoking OpenCode session. The directory query is interpolated without URL encoding, and patch response status is not validated before the success card. This helper is effectful even when used mainly to obtain mobile access information; it was not run.
