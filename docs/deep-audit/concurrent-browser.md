## Architecture and intent

Full mode is an RFB3.8 shared viewer of Blackwall's Xvfb desktop, not merely a webpage screenshot. It includes native tabs, toolbar, extensions, other raised Xvfb windows and shared focus/actions with Remmina. Page mode uses pinned Casty1.3.3/CDP against the same Chrome profile, creates its own tab, applies a viewport override and clears that override on normal exit; it deliberately leaves the tab open. Arch connects via a private temporary loopback SSH forwarding to5900 or9222. connection.py starts existing cloud-chrome.service, waits CDP, optionally opens URL, invokes ensure-window.sh, activates Chrome and returns existing password over SSH. Do not invoke it as a read-only status probe.

039deb4 initially used floating graphics;8653401 replaces them with Unicode placeholder cells, adds synchronized frame output, periodic refresh, viewer/tunnel supervision, parent-death signalling, window passthrough leases and browser input mode. The direction is native browser functionality embedded within an existing terminal workflow, session continuity, reversible settings and preserving sibling panes/browser state. These are source/commit intent; direct owner statements require the concurrent session archive.

Full viewer decodes raw/zlib VNC rectangles and maps scaled terminal-cell mouse input through letterboxing. Page rendering patches Casty to skip creating/downloading Chrome, use existing CDP and avoid shared Browser.close/process kill. Installer pins source commit, locked ws8.22.1 and patch/data/lock fingerprint, backs up stale runtime/foreign launcher and uses private Python venv. It still depends on installed host SSH/Node/npm/Git/Python/tmux/compatible terminal and Blackwall service setup.

## Evidence and findings

CB001 — reproduced source behavior: releasing a pressed mouse button in the full viewer's letterboxed region returns before updating self.buttons. Next in-bounds motion still sends button1 held. A pure AST-selected View class probe with Fake pointer/key receiver yields masks1→1 and next motion[25,15,1]. No module import, socket, clipboard, UI or tmux operation. Evidence: verification/browser-letterbox-release.json. This is a bounded model-level reproduction, not a physical Chrome drag test; no fix applied.

CB002 — lifecycle test coverage limitation: test-close.py descendants() filters commands to launcher/desktop.py/casty only. SSH tunnel children do not satisfy that filter, so assertions that those selected processes exit do not independently prove tunnel cleanup. Launcher source does call stop(tunnel) and parent_death; preserve distinction between implemented mechanism and the test's selected-process evidence.

CB003 — real Kitty pixel test is deliberately a renderer fixture: test-lifetime.py feeds a solid marker image via Fake desktop snapshot or direct patched kitty.js. It tests graphics hide/return/resize/move/close, not real Chrome content or launcher lease/input cleanup in the same test. test-full/test-pane/test-close supply separate integration paths; handoff all-passed prose needs raw session outputs. None were re-run by audit because they manipulate shared desktop focus/browser state.

CB004 — input management scope: mode.py installs namespaced hooks but changes session prefix/prefix2/key-table/assume-paste-time and session mouse based on that session's active pane/window; it switches every attached client in the session. Thus pane-scoped product phrasing describes conditional activation, while actual input settings are session-wide. Multi-client behavior is not established by single-client fixtures. Fixed hook index9348/key-table names assume ownership of that namespace. Lease records are per server/window and use PID/starttime to discard stale owners. Stale state restoration relies on future sync/release; SIGKILL itself cannot run launcher finally.

Primary check: Kitty's specification says U+10EEEE placeholders are normal text cells that hosts such as tmux can move; U=1 creates a virtual placement and three diacritics encode row/column/high image-ID byte. This supports the rendering design and why deleting underlying pane cells changes visibility. The explicit implementation still needs terminal acceptance; source protocol compliance alone is not it. https://sw.kovidgoyal.net/kitty/graphics-protocol/#unicode-placeholders . Pinned upstream kitty.js source was opened and full198lines read, confirming original global d=A cleanup and floating placement behavior altered by local patch: https://raw.githubusercontent.com/sanohiro/casty/f72ecdd21bc8795fe673dce0d27f49a281273e78/lib/kitty.js .
