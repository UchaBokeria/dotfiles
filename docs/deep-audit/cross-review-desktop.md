## CD001 — Wallpaper generation does not reload SwayNC CSS

`theme/blackwall_theme/__main__.py:48` writes the live SwayNC style.css. `scripts/setwall:69` regenerates targets, then its entire reload fanout (:86–139) reloads Hyprland, Waybar, Eww, Mako, Kitty, tmux, GTK theme and Cava, with no SwayNC CSS reload. Autostart adopts an already running SwayNC rather than restarting it. Quiet's `save_config` calls only `--reload-config` (`scripts/blackwall-quiet:172`).

In the matching upstream code, initial startup loads CSS, `reload_css` calls Functions.load_css and `reload_config` reloads JSON/widgets without that call. The pinned README specifies a separate CSS-reload command. Sources: [v0.12.6 functions](https://raw.githubusercontent.com/ErikReider/SwayNotificationCenter/v0.12.6/src/functions.vala), [daemon methods](https://raw.githubusercontent.com/ErikReider/SwayNotificationCenter/v0.12.6/src/swayncDaemon/swayncDaemon.vala), [README](https://raw.githubusercontent.com/ErikReider/SwayNotificationCenter/v0.12.6/README.md). Thus successful generation/text parity does not establish immediate notification palette application. This is a static missing-reload path, not a live reproduced visual failure. M018 correctly limits itself to text equality; the broader “whole rice” wording needs this runtime qualification.

## CD002 — A wallpaper change resets WhatsApp's in-memory Vim engine

`cmd/wa/main.go:258` wires file-change watching into the UI. `internal/ui/app.go:649–651` handles an external reload by rereading config, `events.go:91–94` applies it, and `app.go:382–405` constructs a fresh Engine and a fresh empty Registers map, preserving only the current mode. `internal/vim/engine.go:54–91` stores macro recording/replay, pending/count/operator and dot-repeat state on that discarded Engine; `register.go:40–41` creates an empty register map.

Therefore a palette-only write from setwall follows the same path as keymap reconfiguration and discards local yank registers, stored macros, dot-repeat and half-typed sequences. This conflicts with the design guide's continuity of keyboard operation even though the visual theme updates correctly. Per-chat drafts/undo and app-owned marks are separate structures; this finding does not claim their deletion. `reload_test.go` checks that Restyle is called and listening continues, without preserving editor state. No live draft, clipboard or macro was used to reproduce it.

## CD003 — Theme-error fallback uses startup colors rather than latest valid colors

The Restyle closure at `cmd/wa/main.go:280–287` catches loadPalette failure and chooses `s.styles.Palette`, which was created in loadState at:154 and is never updated when the UI receives later styles. `app.go:405` applies returned styles to the App, not to that captured state. A startup palette A followed by successful B then malformed C therefore selects A, despite the comment promising colors already on screen. The theme-loading error is also converted into a style result, allowing the config-reloaded status path; it is not surfaced as a reload error by this closure. Static source composition; installed executable has dirty-build provenance (M021), so present-binary behavior is not asserted.

## CD004 — Theme-watch coverage is narrower than its all-files claim

`cmd/wa/main.go:519–563` promises every file loadPalette/config.Load may read. Its directory map is fixed to wa config/overrides/theme.toml and three standard cache paths; it receives no cfg argument. An explicit `Theme.File` at an arbitrary path is honored by basePalette (:588–590) but not added to watchers. Setting that path during a hot reload does not rebuild the map. Direct edits to the custom palette do not themselves request a UI reload unless they also happen to match one of the fixed paths.

Missing directories and watcher-registration errors are silently skipped once at startup. A cache directory first created later is never watched, and fsnotify-internal errors are ignored by `config/watch.go:runFiles`. These are bounded source limitations; they do not prove the presently configured standard paths are missing. Manual :reload or another watched-file event can still pick up the custom file. This qualifies the intended hot-reload contract without treating it as entirely absent.

## CD005 — The documented wallpaper opt-out does not override generated wa/theme.toml

`whatsapp/README.md:453` says follow_wallpaper=false retains built-in colors. `basePalette` instead resolves explicit file, then existing generated `<ConfigDir>/theme.toml`, and only then checks FollowWallpaper before raw cache fallback (`main.go:587–606`). On a rice installation where generated theme.toml exists, toggling this setting alone keeps following the generator. The root/embedded TOML comments also say empty file means built-in, although empty file actually enables the precedence chain. The implementation may intentionally prioritize the central generator; the discrepancy is the advertised opt-out semantics, not the centralized-palette design itself.
