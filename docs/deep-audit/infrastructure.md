## Architecture and intended taste

The install path is a Bash bootstrap doorway into a Ratatui Rust planner/executor. The catalogue owns packages, links, settings, setup commands and questions; probe derives machine state, plan renders a reviewable delta, Runner executes that approved list on a worker and streams bounded UI logs (`installer/src/main.rs:101`, `installer/src/plan.rs:66`, `installer/src/exec.rs:138`). Core packages are mandatory, optional groups start off; per-machine Lua is generated from detected answers rather than hard-coded universal hardware (`installer/src/main.rs:109`, `installer/data/questions.toml:15`). AUR installs run one package at a time so one bad PKGBUILD cannot prevent independent packages from installing (`installer/src/exec.rs:193`). Copies belong to the user, symlinks stay source-owned, generated files are excluded from links (`installer/src/plan.rs:148`). Originals go to timestamped backup storage; created paths are tracked separately.

The desktop is an explicit adapter architecture. Eww renders state handed to it; Bash/Python helpers gather system truth as JSON, own mutations, and push fresh state after actions. UI helpers detach before calling Eww back, preventing the daemon from waiting on a child that is waiting on its parent (`scripts/blackwall-cal-ui:13`, `scripts/blackwall-net-ui:17`, `scripts/blackwall-clocks:10`). Text entry goes through Rofi, because this deployed Eww focusable mode would exclusively capture the keyboard (`scripts/blackwall-cal-ui:32`). Per-application volume moves live streams as well as changing default devices (`scripts/blackwall-audio:66`). Network credentials are reused by actual SSID instead of assuming NetworkManager profile names equal SSIDs (`scripts/blackwall-net:190`). The implementation repeatedly favors observed state changes over a command merely returning.

Autostart is unconditional on every configuration pass but serialized and idempotent. It waits up to 20 seconds for a nonzero output, uses exact executable names, handles kernel comm truncation, adopts existing script daemons via /proc, and closes its flock descriptor in spawned children (`scripts/blackwall-autostart:23`, `:44`, `:91`, `:124`, `:145`). This is a direct response to earlier duplicate bars/watchers and missed compositor-start events, recorded in source comments. Waybar/Eww/wallpaper, notification bus owner, clipboard watchers and rice daemons are session-launched, while ArchPilot is a restartable default-target user service that discovers the compositor later (`archpilot/systemd/archpilotd.service:5`, `archpilot/src/archpilot/compositor.py:24`). A stale-linked glass plugin triggers a background rebuild, so startup includes network/build/reload effects rather than merely launching existing binaries (`scripts/blackwall-autostart:248`, `scripts/blackwall-glass:47`).

Notifications have three separate lifecycles: the bus daemon displays, notifyd records bounded persistent history, watch evaluates high-signal conditions. Watch uses cooldowns, three-strike suppression, stable condition keys, recovery resets, mutes, hysteresis, severity ratchets, delayed rechecks and explicit failed-probe handling (`scripts/blackwall-watch:82`, `:93`, `:159`, `:274`, `:362`). Destructive work is attached to clicked actions; update notifications deliberately offer review rather than running upgrades (`scripts/blackwall-watch:557`). Quiet distinguishes muted (history retained) from ignored (discarded), serializes config/state writes, refuses corrupt live config replacement, creates transient expiry timers and repairs expired mutes after reboot. DND gets an explicit visibility rule ahead of SwayNC critical-bypass behavior (`scripts/blackwall-quiet:125`, `:186`, `:441`, `:555`). This makes silence a user-visible contract rather than a notification toggle that critical alerts ignore.

Wallpaper theming is palette extraction followed by derivation, then independent reloads fanned out in parallel. Threshold fallback supports nearly monochrome images. It intentionally reads source through /usr/local/bin symlinks instead of stale copied scripts (`scripts/setwall:1`, `:50`, `:90`, `scripts/link-bin:4`). Snapshot recovery uses file copies to cover dirty/generated/external toolkit state that Git alone misses, and keeps its own current source when restoring (`scripts/blackwall-snapshot:10`, `:168`).

ArchPilot is a stdlib daemon/CLI with a system-Python GTK client, newline JSON Unix socket, external Claude/Codex/OpenCode engines and real CLI-owned resumable sessions. Its safety layers differ by engine: Claude flags plus PreToolUse classifier and armed askpass, Codex sandbox, OpenCode agents/own permissions. Clearing ANTHROPIC_API_KEY in the service is a subscription-billing guard, not a universal provider-key scrub (`archpilot/systemd/archpilotd.service:25`, `archpilot/src/archpilot/modes.py:45`, `:182`). Runtime files fall back to owned 0700 per-user /tmp storage. The hook exits 2 on unexpected failure and clamps its deadline below harness timeout (`archpilot/hooks/pretooluse.py:44`, `archpilot/src/archpilot/config.py:196`). These are source contracts; historical CLI probes in AGENTS/hook-contract still require current-version revalidation before runtime acceptance.

The newest terminal intent is recorded in `tmux/AGENTS.md` and HANDOFF: persistent nested workspaces, full-terminal picker including status row, immediately centered buffered first frame, compact in-context overlays, Vim-modal reactive fuzzy search, aligned rounded/capsule Arch styling, empty new workspaces, explicit session creation, retained multi-selection and no live server restart. ## New findings and review implications

- **INF-001 — bootstrap dry-run is effectful.** `install:68-99` may install Rust, refresh sudo and build before forwarding --dry-run to the Rust program. The Runner dry-run guard applies later. The wrapper also uses exec after installing an EXIT trap, so the sudo keepalive may survive the wrapper replacement: treat as a lifecycle concern pending controlled isolated reproduction.
- **INF-002 — custom status command can start wallpaper daemon.** `scripts/blackwall-autostart:180-187` launches awww-daemon on failed query without testing status_only. Even normal status creates/updates runtime logs/lock and may adopt pidfiles. Do not treat this command as read-only.
- **INF-003 — external restore loses absolute-root identity.** `installer/src/exec.rs:245-247` stores /etc or /usr paths relative to /, but `:425` restores all under HOME. `scripts/blackwall-undo:134` repeats HOME reconstruction. Link root metadata only triggers a sudo readiness check; filesystem work itself remains in the user process. These limitations matter if non-home links are added or used; the current catalogue limitation is narrowed by INF-021 below.
- **INF-004 — after is documentary, not scheduler input.** `installer/src/data.rs:146` parses dependencies, but `installer/src/plan.rs:247` iterates original step order. This contradicts `installer/data/README.md:34`. optional similarly has no observed planner branch. A catalogue reorder can violate dependency intent.
- **INF-005 — installer text-row keys conflict with navigation.** `installer/src/main.rs:351-378` handles j/k before text input and catches all remaining keys in the text-row arm, swallowing Enter/Escape there. A selected credential row cannot advance with Enter or accept j/k as characters; the user must navigate away to advance.
- **INF-006 — installer abort wording overpromises.** Running q immediately sets quit and returns the main loop (`installer/src/main.rs:442`, `:558`); the worker has no cancellation flag. Footer says abort after current step (`installer/src/ui.rs:541`). Child subprocess cleanup/continuation is unverified.
- **INF-007 — VPN UI calls absent verbs.** `scripts/blackwall-net-ui:96-102` invokes ts-dns/ts-routes, advertised in VPN help, but `scripts/blackwall-vpn:418` onward has no cases. ts-exit is also help-only. Static consequence: clicks end in unknown command rather than applying settings.
- **INF-008 — Bluetooth UI bypasses pairing helper.** `scripts/blackwall-net-ui:64-70` calls bluetoothctl connect directly; `scripts/blackwall-net:218` has the missing pair/trust flow. The more capable CLI backend does not apply to this UI route.
- **INF-009 — Wi-Fi 6 GHz label unreachable.** `scripts/blackwall-wifi.py:94` checks >=5000 before >=5900, so 6 GHz is always 5G. Its saved marker compares profile names (`:21`) although actual connect code correctly resolves saved SSIDs; renamed profiles may display unsaved.
- **INF-010 — degraded audio status can be invalid JSON.** dev_state emits {} on wpctl failure (`scripts/blackwall-audio:37`); composition at `:177` strips braces but retains the preceding comma. Missing/failed device readings can therefore become {desc: value,} rather than a valid empty state.
- **INF-011 — snapshot coverage has deliberate and accidental holes.** TREES omits swaync, tmux, nvim, fish, ArchPilot (`scripts/blackwall-snapshot:40`), despite covering things that paint a pixel. diff skips stored standalone files (`:248`), including starship.toml. Save/shot names have one-second resolution (`scripts/blackwall-snapshot:82`, `scripts/blackwall-shot:116`), so rapid calls can merge/overwrite. Safety snapshot may share a just-created source timestamp; controlled reproduction remains pending.
- **INF-012 — ArchPilot reversibility guarantee excludes already-dirty files.** policy allows in-repo Write/Edit as Git-revertable (`archpilot/src/archpilot/policy.py:90`), but commit_changes computes only newly dirty path names (`archpilot/src/archpilot/git.py:67`). Further edits to already-dirty files are not committed. A failed add/commit runs unscoped git reset -q (`:77`, `:84`), potentially unstaging unrelated owner work. Auto-commit success is not equivalent to capturing all agent edits.
- **INF-013 — ask means policy-reversible, not strict read-only.** policy permits playerctl and blanket hyprctl/eww/wpctl/brightnessctl (`archpilot/src/archpilot/policy.py:113`, `:178`). Runtime mutations remain allowed despite ask documentation. Lua arbitrary execution is outside the legacy forbidden-subcommand shapes, a further reason to avoid treating this classifier as a shell security boundary. No adversarial execution attempted.
- **INF-014 — sensitive state must stay outside authored tracking.** .gitignore excludes fish universal variables, editor backups, snapshots and OpenCode pem keys, with explicit historical-secret explanations. AGENTS warns untracked sparkcode contains plaintext provider material. Universal variables have now been read with credential values redacted; sparkcode control flow has been read with provider lines excluded. A later redaction failure is disclosed in pass 4. No credential values belong in audit reports.
- **INF-015 — notification history concurrency differs from quiet state.** quiet has a shared flock/atomic replace, whereas notifyd appends then rewrites to trim and blackwall-notify clear/drop rewrite without shared locking (`scripts/blackwall-notifyd:42`, `scripts/blackwall-notify:91`). Simultaneous incoming notifications and drops can lose or restore entries. History bounds record count, not payload bytes.
