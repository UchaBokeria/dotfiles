## SH002 — The upstream aesthetic predates Blackwall and grew from one scene

The first commit450c888 (2022-01-27) is a Sugar Dark/Sugar Candy-derived astronaut greeter. Historical screenshots show the same illustrated astronaut and large pale moon with an initially small RobotoMono greeting/clock, translucent dark inputs, user-dropdown icon, show-password checkbox and tiny power controls. Later previews enlarge and bold the clock, switch to Open Sans, remove the explicit checkbox in favor of the password-field icon, and explore crisp wallpaper, a full-screen blur, and a blurred form-width region at center or left. These are visually inspected alternatives from upstream, not evidence that the owner requested each one.

Commit1ede3c2 (2024-04-06) changes layout/fonts/configs;f424328 (2024-12-10) expands color settings and removes the old dedicated UserList component. Commitc9a8ab4 (2025-01-04) changes a one-theme project into a ten-theme catalogue, adds setup.sh, themed display fonts, animated backgrounds and descriptive names. The current wallpaper assets are exact descendants already inspected in desktop.md. Retaining the full catalogue does not mean all variants are actively selected. Font specimens confirm the historical monospaced family has deliberately different thin/light/regular/medium/semibold/bold and italic forms, rather than14 anonymous binary duplicates.

## SH003 — Compatibility migration also changed the material implementation

Commitd845917 (2024-03-08) ports Qt5 imports to Qt6/Plasma6 with Qt5Compat graphical effects. Commit3ff1700 (2024-09-11) removes that compatibility layer, replaces GaussianBlur with MultiEffect and drops dropdown shadows; related configuration removes InterfaceShadowSize/Opacity and substitutes Blur/BlurMax for BlurRadius. Thus a retained old shadow-heavy config is not interchangeable with current renderer settings.

Commitba024e7 (2024-12-31) adds AnimatedImage/GIF speed and fixes blur geometry when full blur, opaque form background and a side-positioned form interact. Commit8a6ed16 adds QtMultimedia video playback, then c9c5920 handles placeholder/background loading and more video extensions. Source uses looping media, crop/fit alignment and optional placeholder imagery; there is no evidence here that runtime video playback was accepted on this machine. Current master still carries the established1080p-oriented ratio/font layout; dev's separate scaling work changes how text, padding, rounding, icons and blur respond to resolution.

## SH004 — Login evolution is about visible identity and keyboard usability

Historical Input versions show a show-password checkbox becoming a checkable password icon with focused/hovered/visible states; Return/Enter dispatch moved between button handlers and direct login calls. Session controls moved between Main, Input and LoginForm; popup geometry and arrow-key navigation were repeatedly simplified. Commit7123e38 (2024-12-23) explicitly fixes system-button array bounds and adds an option to bypass capability checks. All these are observable UI mechanics, not merely palette changes.

The older interface transformed usernames to lowercase by default, with variants named AllowBadUsernames then AllowUppercaseLettersInUsernames. Commit292c87b (2026-07-06) switches to MixedCase display, allows optional real-name/GECOS display and maps either account name or real name back to the actual login name through a hidden registry. Its theme comments warn that duplicate real names cannot be distinguished and recommend disabling UseRealName in that case. This is the rationale for current source differing from installed older Input.qml; it should not be described as an accidental capitalization drift. The dev-only profile-picture work exposes the matched user icon with a fallback silhouette, configurable mask/ring and scaling. No account or password was submitted during this review.

## SH005 — Installer history preserves real operational hazards and repairs

The early setup.sh is an interactive shell menu performing package installation, shallow cloning, backup/move, copying theme/fonts and overwriting `/etc/sddm.conf` and virtual-keyboard configuration. A missing `/etc/sddm.conf.d` creation is later repaired (22bbb5e); umask022 (3fcf17f/6b30748) addresses themes unreadable to SDDM under restrictive user defaults. Array indexing and a non-POSIX arithmetic/read style lead to a Bash shebang repair, and later README launcher changes from sh to bash for dash systems.

The Gum rewritea99918b (2025-08-25) adds strict-shell execution, optional Gum installation, better prompts, package-manager selection and restart behavior. Its early clone path deletes an existing checkout; laterf759e87 replaces that deletion with a timestamped backup. Restart changes from exec $0 to invoking main because download-and-evaluate launch does not provide a stable executable script path. Void package-manager detection regresses through shortened xbps names and is repaired to preserve the actual xbps-install command (400f63b). Dependency lists change for Debian/openSUSE as upstream compatibility evolves; those historical names are not current installation recommendations.

Commit ed6229a adds systemd/openrc/runit/dinit support, including disabling other display managers and sometimes starting SDDM immediately. September master merge improves runit service/config directory discovery and installs the Artix-specific service package only when os-release identifies Artix. These scripts can replace system configuration, disable the current display manager or start a greeter; they are not safe read-only probes. Their historical success messages do not establish successful installation here. The current branch's backup behavior preserves theme directories but its explicit tee still replaces the main SDDM config; current source review and installed comparison remain in desktop.md.

## SH006 — Documentation and source explain alternatives, not owner intent

Documentation progresses from minimal clone/config commands to distribution dependencies, greeter preview instructions, ten-theme previews, source/art credits, automatic installer and community NixOS overrides. Some historical README variants say edit a file while the included command replaces it with tee; later wording clarifies that it is a command. The preview guide itself warns that test-mode appearance can differ from the actual login screen. We therefore retain the distinction between source review, preview assets, installed file comparison and physical greeter acceptance.

Upstream comments and messages provide evidence of upstream design rationale and observed compatibility problems. They do not identify the Blackwall owner's authorship or preference beyond the actual current selection and independently preserved owner instructions. The SDDM material supports an inference of attraction to illustrated atmospheric scenes, large quiet time typography and translucent controls; deployment evidence specifically narrows selection to the older Japanese variant. The exhaustive catalogue and dev history should not be flattened into one supposedly active design.
