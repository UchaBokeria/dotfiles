## Architecture and taste

`main.tsx` loads fonts→tokens→base→glass→shell→views→app additions→responsive CSS, then mounts React StrictMode with theme/toast providers. `App.tsx` chooses checking/sign-in/dashboard from the auth store, uses hash routes for Home, Console, Feed, Runs, Explain and Settings, updates title/focus on navigation and exposes a Ctrl-K palette. No client router dependency is needed. API types import backend payload types as erased type-only imports (`api/types.ts`); this prevents compile-time shape drift without bundling server code. Runtime JSON is trusted rather than schema-validated in the page.

The visual system explicitly records its relationship to readb mockups in `styles/tokens.css:1`: warm Claude-orange accents over charcoal neutrals, Inter text and JetBrains Mono numeric/tabular data, four-point spacing,8/12/16/24/28px radius tiers, pill buttons, round icons and semantic state/container/on-container pairs. Alternate Tide, Aurora and Mint provide teal, violet/cyan and electric-mint directions, each dark/light. Default preferences are Claude, flat, system mode (`lib/prefs.ts:22`); glass is optional, not evidence the owner selected it here. CSS repeatedly says state is a gradient wash rather than a colored side stripe. The glass recipe layers blur/saturation, tint, semantic wash, sheen, inner edges, lensing ring and shadow (`styles/glass.css`), with12/22/32px blur and180%saturation. Reduced motion and partial reduced-transparency fallbacks are explicit. Bundled local font subsets and embedded icon paths avoid CDN/font-icon dependencies. Selected navigation uses filled symbol variants. The viewed logo is a single orange musical note on three grey staff lines, with a rounded dark favicon tile.

The desktop resemblance is real in tokens and materials; shared ownership/adoption of every upstream choice is an inference, not established by source presence. Flat/system defaults, alternate palettes, and manual browser-local persistence are distinct from Blackwall's wallpaper-driven generated palette pipeline. There is no `blackwall-theme` import or automatic wallpaper palette subscription in these55files.

Data polling deliberately supports a glance board: Home/ladders15s,catalog30s,feed20s,run detail10s. `lib/poller.ts` serializes reads and drops refresh requests during an in-flight read; it always fills once even in a background tab, then pauses while hidden or unfocused beyond60s. `usePoll.ts` aborts on unmount/path change and keeps last good data after failures. Local elapsed times tick without server traffic. Home separates partial payload errors and stale readings; scores remain null/empty when unscored, with a disclosed Artificial Analysis basis rather than fabricated numbers.

## Discovery pass findings

**SU001 — “Serving” accounts means only “not inferred capped.”** `lib/accounts.ts:71` sets capped solely from the optional cap field, and90–92computes serving as total minus capped. `views/Home.tsx:24–28` gives every other account a green Serving badge and108–109counts “accounts serving.” The backend `GoGatewayLimits` has gateway, plan, estimated windows and optional cap, without enabled/auth/recent-success data (`src/go-limits.ts:61–72`, also independently full-read by history agent). `computeLimits:253–275` includes each Go-URL gateway without an enabled check. Further, `capOf:370–377` clears cap whenever the last status is anything other than429, including401/403, contrary to its stronger success-only documentation. Therefore a disabled, never-used or refused account can be presented as Serving; source proves the inference mismatch, not that it is happening in the live dashboard. Estimated usage/footer is disclosed correctly, but does not qualify the green availability claim.

**SU002 — Request health and router reachability are conflated; stale panes are unevenly disclosed.** `api/client.ts:58–61` throws for any non-OK HTTP response. `hooks/usePoll.ts:48,56` reports success/failure into one shared latest-completion boolean, while `App.tsx:97–101` labels false Router-unreachable and true Router-healthy. A404/500is evidence of an answering HTTP endpoint; one successful sibling poll can replace another endpoint's failure. Home visibly labels last-good data (`Home.tsx:93`), but Console58/73, Feed41and Runs127only show failures when no previous data exists. Once filled, those panes retain stale content with no per-pane age/error disclosure. The top badge alone cannot identify which source failed or how old each pane is. This is source-level behavior, not an observed outage.

**SU003 — Gateway and model switches display effective state while writing independent raw flags.** `lib/settings.ts:37–52` infers a gateway enabled from any enabled model, with true for no models. Backend catalog `src/native/ui-catalog.ts:236` uses `isTierCandidateEnabled`, which combines model and gateway flags (`src/config.ts:1300–1309`). The model switch writes only `models.<key>.enabled`, and gateway switch only `native.gateways.<name>.enabled` (`Settings.tsx:228–246`, backend `src/console/settings.ts:485–499`). With a gateway disabled, a model switch appears off; clicking it writes model true but cannot override gateway false. Conversely, with all individual models disabled, the gateway appears off; clicking it writes gateway true but leaves all models disabled and the same off presentation. The source comment acknowledges inference, but the binary “Use” switch does not expose that distinction to the person operating it. Backend validation can reject configurations that remove every enabled tier candidate; that safeguard does not make the displayed flag identities equivalent.

**SU004 — Budget copy reverses covered and priced cost.** `lib/settings.ts:12` describes today's “covered cost” passing the budget; `Settings.tsx:277` calls the field covered cost per day at which alerts fire. Actual `src/budget.ts:45–69` explicitly excludes `price.source='covered'` and unpriced rows; `src/console/events.ts:550–555` likewise bases budget events on priced spend only. Covered subscription work is the opposite class. This wording can mislead the owner about whether subscription list value or actual metered spend controls a financial setting, despite the implementation correctly distinguishing them.

**SU005 — Responsive simplification removes accessible names and over-scopes button sizing.** At721–1100px, `styles/responsive.css:19–23` hides navigation text; `App.tsx:62–70` supplies no independent link aria-label/title, and `Icon.tsx:24` hides unlabeled SVGs from accessibility. The icon-only rail therefore loses its link names at that breakpoint. At≤720px, responsive69hides `.btn-filled .btn-label`, affecting the top Explain-last-call link (`App.tsx:103–104`) and Explain submit button, whose icons are decorative and lack alternate names. Nav text returns at229for the phone tab bar, so its missing-name issue is specifically the intermediate rail range. Responsive72–76also applies width40px to **every** filled button, overriding base `.btn-block {width:100%}` on Login's full-width filled submit (`Login.tsx:49`); its text lacks btn-label and remains. That is a source cascade mismatch; no rendered clipping, actual accessible tree or physical-device acceptance is claimed.

**SU006 — Declared modal state does not confine keyboard focus.** `components/Dialog.tsx:17–28` focuses the wrapper and restores the previous element, with a window Escape handler, but has no Tab-cycle handling or inert background. `Palette.tsx:40–63` focuses search and handles arrows/Enter/Escape only on that input; it neither traps focus nor restores the opener. Both set aria-modal=true while the surrounding dashboard remains ordinary focusable DOM. Tab traversal can leave the purported modal; Escape on a result button is not caught by the palette's input-only handler. Source review establishes missing focus management, without claiming a tested browser/screen-reader result. Existing skip link, labels, focus outline, dialog title and reduced-motion work remain positive features.

**SU007 — Zero-valued meters still draw a nonzero segment.** `components/ui.tsx` correctly clamps fractions through `lib/format.ts:barWidth`, and Console explicitly says unscored models keep an empty bar. However `styles/base.css`'s `.bar > i` has `min-width:4px`; the same element receives width0%for an unscored or zero-used row. That CSS minimum preserves a visible colored sliver despite a numeric zero/null. It is a bounded visual encoding inconsistency rather than fabricated stored score data or a native rendered measurement.

## Traced workflows

Appearance: Settings Appearance or Ctrl-K command→ThemeProvider.set→savePrefs JSON in `sonata.theme` localStorage→applyPrefs data-palette/data-glass/data-theme on html→token blocks and scoped glass rules. Storage errors are caught; preferences work for that page but persistence can fail silently. `index.html` duplicates the parsing/application before first paint. No theme-setting API request occurs.

Tier reorder: Settings TierEditor draft from tierEntries→drag or arrows→Apply→tierPath→patchSettings requires current CSRF meta→PATCH `/__sonata/api/settings`→backend reorder-only handler validates the submitted membership and preserves disabled slots/collapsed role behavior (`src/console/settings.ts:379–395,500–523`)→success toast plus ladder/catalog/limits refresh and settings snapshot reread. This distinguishes deliberate config writes from browser-local appearance. No writes were issued by the audit.

Run termination: RunDetail's live payload→Kill visible only for running state, disabled without CSRF→confirmation Dialog→POST encoded `/run/:id/kill` with CSRF→toast and refresh. Transcript/report text uses React text/pre rendering, not HTML injection; truncated data is explicitly marked. The confirmation says existing disk work remains and report may be missing, accurately presenting the action's consequence at the UI boundary; server enforcement belongs to the backend review.

Sign-in: missing CSRF starts checking→auth probe403means sign-in required, other/unreachable status yields read-only dashboard→username/password login POST→successful reload receives HttpOnly cookie-backed page/meta. Any later GET403on a signed-in page switches back to login. Source header comments still discuss dashboard secret links alongside the newer password screen; backend auth implementation decides which routes are actually enabled.
