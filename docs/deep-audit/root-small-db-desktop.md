## Architecture and taste recovered

The historic Blackwall scheme separates wallpaper extraction from editor color roles: Wallust renders cache JSON; the theme emitter generates `custom.blackwall_palette`; `colors/blackwall.lua` maps roles into highlights and terminal ANSI entries. The blue-grey palette captured here is a historical wallpaper handoff, not today's orange palette. Opaque raised/sunken surfaces and restrained accent roles are explicit source comments, so they can be credited as authored design intent. Actual terminal composition remains a separate layer. The legacy transparency helper uses `nvim_set_hl` with background-only specs, with call sites commented out; its mere existence is not evidence it was running.

Theme persistence had several independent owners: startup plugin setters, a config-directory state file silently skipped when its directory was missing, a Telescope live preview/revert lifecycle, and the broken historical `SetTheme` argument handoff. The implementation tail replaces that arrangement with a data-directory state path, a default Blackwall selection and startup restoration after plugin setup. Headless checks observe the latter behavior; they do not provide native visual acceptance. The same historical init starts with an unconditional notification no-op, and the utilities plugin captures that no-op as `real_notify`; this is corroborating historical origin for the already recorded notification-suppression issue, not a novel present defect.
